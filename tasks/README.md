# タスク管理（カンバン / WBS）

タスクの実体はこのフォルダ配下の Markdown です。リポジトリ直下の `view.html` は表示と更新だけを行い、
データを持ちません（`view.html` 自体を更新する必要がないので、コンフリクトはタスク単位の Markdown に限られます）。

## 使い方

1. `view.html` を Chrome または Edge で開きます（ファイルをダブルクリックするだけで、サーバーは不要です）。
2. **フォルダを開く** で `tasks/` と `data/` を含むフォルダ（リポジトリのルート）を選び、編集を許可します。
3. **カンバン** / **WBS** を切り替えて利用します。**＋ 新規追加** でタスクや項目（フォルダ）を追加できます。エディタや `git pull` で Markdown を変更したら **↻ 更新** で読み直します。

Firefox / Safari などファイル書き込みに対応していないブラウザでは読み取り専用で表示します。

## フォルダ構成

```text
view.html
tasks/
  01-大項目/
    README.md            … 大項目の名前と説明
    01-大項目直下のタスク.md
    01-中項目/
      README.md          … 中項目の名前と説明
      01-中項目直下のタスク.md
      01-小項目/
        README.md        … 小項目の名前と説明
        01-タスク.md
        02-タスク.md
data/
  holidays.md            … 祝日・全員の休日
  leaves.md              … 担当者ごとの休み
```

- フォルダ名が項目名、ファイル名がタスク名です。先頭の数字はタスク番号（作成順の識別子）で、章番号ではありません。
- 大項目・中項目・小項目の階層はフォルダ構成で決まります。大項目直下のタスクに中項目以下は不要、中項目直下のタスクに小項目は不要です。
- 各フォルダの `README.md` に項目の `name` と説明を書きます（省略時はフォルダ名を使います）。この `tasks/README.md` はタスクとして扱いません。
- 章番号（`1.2.1` など）は保存せず、表示のたびに着手予定日の早い順に階層ごとに振り直します。
  同じ日付の場合は `order`、タスク番号の順です。項目の日付は配下のタスクで最も早い着手予定日です。

## フロントマター

```markdown
---
name: ログイン画面の実装
status: 着手予定
type: タスク
category_large: 開発
category_medium: 認証
category_small: 画面
estimate_hours: 10
actual_hours: 0
assignee: 山田
start_date: 2026-11-19
updated_date: 2026-11-18
completed_date:
depends_on: [01-02-01-01]
---

ここから下が本文です（view.html でタスクを選択すると編集できます）。
```

| キー | 内容 |
| --- | --- |
| `name` | タスクの名前（省略時はファイル名） |
| `status` | タスクの状態。`着手前` / `着手予定` / `進行中` / `完了` / `対応不要` |
| `type` | タスクの種類。`大項目` / `中項目` / `小項目`（README.md）/ `タスク` |
| `category_large` `category_medium` `category_small` | タスクの分類名。ファイル単体で読むための記載で、表示はフォルダ構成に従います（不一致は画面に注意を表示） |
| `estimate_hours` | 見積もり時間。WBS では 1 日 5 時間稼働として日数に換算します |
| `actual_hours` | 作業時間 |
| `assignee` | 担当者 |
| `start_date` | 着手予定日付（`YYYY-MM-DD`） |
| `updated_date` | 更新日付。view.html から更新すると自動で記入します |
| `completed_date` | 完了日時。`完了` にすると自動で記入し、`完了` から戻すと空にします |
| `depends_on` | 依存するタスクのタスク ID。パス上のタスク番号を `-` でつないだもの（`tasks/01-…/02-…/01-…/01-….md` → `01-02-01-01`） |
| `order` | 同じ着手予定日のタスクを入れ替えたときに view.html が記入する並び順 |

ここにないキーを自由に追加できます。view.html は変更したキーの行だけを書き換え、他の行や本文はそのまま残します。

## 新規追加と対応不要

- **＋ 新規追加** で種類（タスク / 項目）と追加先を選んで作成します。タスクは追加先フォルダに `番号-名前.md` を、項目は `番号-名前/README.md` を作ります。
  番号は追加先にある同じ種類の最大番号 + 1 です。ファイル名に使えない文字は `-` に置き換え、正式な名前は `name` に残します。
- 項目は `tasks` 直下（大項目）から小項目の深さまで追加できます。タスクはいずれかの項目の中に追加します。
- view.html からは削除しません。不要になったタスクは状態を `対応不要` にします。ファイルと章番号は残り、WBS ではバーを表示せず、
  依存関係では完了と同じく「待ち」になりません。

## カンバン

- 状態ごとの列にカードを表示し、ドラッグ＆ドロップで `status` を更新します。`完了` に移すと `completed_date` を記入します。
- **範囲** は既定で「進行中のタスクがある中項目（なければ次に着手する直近の中項目）」です。すべて、または大項目・中項目を選んで絞り込めます。
- カードを選択すると名前・状態・担当者・時間・着手予定日・依存関係・本文を編集でき、保存すると Markdown に上書きします（本文は Markdown のまま扱います）。

## WBS

- 大項目 → 中項目 → 小項目 → タスクの順に、着手予定日の早いものから章番号を振って並べます。
- 予定は水色（`着手前` は斜線入り）、進行中は黄緑、完了はグレーです。土日・祝日と担当者の休みは色分けし、稼働日から除外します。
- タスクの日付セルをダブルクリック（または状態のボタン）で状態を変更します。`完了` → `着手前`、`着手前` → `完了` へは直接変更できません（`対応不要` との間はどの状態からも変更できます）。
- ▲▼ で同じ項目内の隣のタスクと入れ替えます。章番号は着手予定日順のため、2 つのタスクの `start_date` を交換します（同じ日付の場合は `order` を記入します）。
- 担当者で絞り込めます。タスク名・項目名を選択すると内容を編集できます。
- `depends_on` の依存先を章番号で表示し、依存先の終了見込より前に着手予定の場合は ⚠ を表示します。

## 休日データ（`data/`）

- `data/holidays.md`: `- 2026-11-23 勤労感謝の日` の形式で祝日・全員の休日を書きます。
- `data/leaves.md`: `- 2026-11-20 山田: 有給` の形式で担当者の休みを書きます。
- どちらも `- 2026-12-29〜2027-01-03 年末年始` のように期間で書けます。
