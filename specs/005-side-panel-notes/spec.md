# Feature Specification: 作業を離れずサイドパネルでメモを書く

**Feature Branch**: `005-side-panel-notes`

**Created**: 2026-09-22

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - サイドパネルでメモを書く（要望005） (Priority: 未決定)

ユーザーは、作業中のコードや文書を中央エディタに表示したまま、QuickNoteMD のサイドパネル内でメモを新規作成し、既存メモを開いて追記・修正したい。

**Why this priority**: 作業対象から離れずに記録する価値を、他の機能のユーザーストーリーと比較して優先順位と実際の提供範囲を決めるため、未決定とする。

**Independent Test**: 中央エディタに任意のファイルを表示したまま、サイドパネル内だけでメモの作成・本文入力・保存・再編集を完了する。Todo の詳細・優先度・ラベルや006のライブ編集方式がなくても検証できる。

**Acceptance Scenarios**:

1. **Given** 中央エディタで作業中である、**When** サイドパネルで新規メモのタイトルと複数行の本文を入力して保存する、**Then** 中央エディタの表示対象を変えずに、通常のメモ一覧から再び開けるメモが作成される。
2. **Given** 既存メモがある、**When** サイドパネル内で選択して既存本文の修正と追記を行い保存する、**Then** 同じメモに反映され、サイドパネル専用の複製は作られない。
3. **Given** サイドパネルに未保存または未反映の入力がある、**When** 別メモへの切替やパネルの非表示・再表示を行う、**Then** 入力が保持されるか、切替前に保存・破棄・キャンセルを選択でき、黙って消失しない。
4. **Given** 同じメモを中央エディタにも開いている、**When** 一方で変更する、**Then** 競合のない確定済み変更は他方でも確認でき、競合時は未保存の入力を上書きせず警告される。
5. **Given** 保存先が使用不能である、**When** サイドパネルで保存を試みる、**Then** 保存失敗と復旧方法が表示され、入力をコピーして退避できる。

### Edge Cases

- 空のメモ、狭いサイドパネル、長文貼り付けでも、入力欄と保存状態をキーボードで確認・操作できる。
- タイトルだけの旧形式の Todo を含むメモ、LF／CRLF、日本語、同名 Todo、末尾改行がない文書を扱っても、意図した編集範囲外の本文や改行形式を変更しない。
- 外部変更、削除・移動、読み取り専用、保存失敗が起きても、古い内容による上書きや成功表示をせず、入力を退避できる。再起動を伴う場合は終了前に標準の未保存確認または退避手段を提供する。
- 表示中に未完成の Markdown や外部コンテンツを含んでも、入力を拒否したり外部スクリプトを実行したりせず、安全な表示を継続する。
- 未知の Todo 記法を通常メモに含む場合、自動処理でその内容を変更しない。003・004が提供されている場合はコメント境界や不明な優先度にも同じ保護を適用するが、それらの提供は受入条件ではない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-501**: QuickNoteMD のサイドパネル内で、通常メモの新規作成、既存メモの選択、複数行の本文の閲覧・追記・修正・保存を完結できなければならない。中央エディタへ移動することを必須にしてはならない。
- **FR-502**: サイドパネルと中央エディタは同じメモを扱い、競合のない確定済み変更を相互に反映しなければならない。新規メモは既存の管理対象・命名規則に従い、通常のメモ一覧に表示する。
- **FR-503**: 保存済み・未保存・保存失敗を区別して表示し、メモ切替、パネル非表示、表示モード変更で未保存入力を黙って破棄してはならない。
- **FR-504**: 通常メモは通常の Markdown ファイルに保存し、拡張機能なしでも内容を読んで編集できなければならない。生 Markdown 表示への切替を常に残し、既存内容の一括変換を導入条件にしてはならない。
- **FR-505**: 競合時は古い内容を黙って上書きせず、失敗理由と再読込・再試行の案内を示し、未反映の入力をコピーして退避できなければならない。既に未保存の他の編集を意図せず保存・破棄してはならない。
- **FR-506**: 意図した編集範囲外の内容、改行形式、同名の別項目を保持しなければならない。未知の記法や曖昧な Todo を Todo 操作では読み取り専用として知らせ、生 Markdown での修正へ案内する。003が提供されている場合、コメント内のチェックボックスを独立 Todo として二重計上してはならない。
- **FR-507**: 新しい操作はキーボードだけで利用でき、状態・保存結果を色だけに依存せず名前で識別できなければならない。004が提供され表示する場合は優先度・ラベルも同様とする。日本語 UI と既存の Windows・macOS・Linux 対応を維持する。
- **FR-508**: Markdown 内の外部スクリプトを実行せず、リモート画像を自動取得してはならない。編集・保存は既存の管理対象だけで行い、表示内容により無関係なファイルを変更してはならない。
- **FR-509**: 003〜006で扱う Todo／タスクカードは担当者属性を持たない個人用項目とし、サイドパネルから担当者の割り当て・表示・保存・権限制御を追加してはならない。

### Key Entities

- **通常メモ**: サイドパネルと中央エディタから同じ内容を閲覧・編集する Markdown 文書。既存の管理対象と命名規則に従い、パネル専用の複製を持たない。
- **編集中の入力**: 文書への反映・保存が終わっていない変更。保存状態、競合、退避可能性をユーザーに示す対象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-501**: 中央エディタの表示対象を変える操作0回で、サイドパネルからメモの新規作成、3段落の記入、保存、既存本文の修正を完了できる。
- **SC-502**: 競合・保存失敗・パネル非表示と再表示・メモ切替・表示モード変更・外部での削除や移動を含む境界ケースで、未保存入力の無警告消失と対象外内容の意図しない変更が各0件である。外部スクリプト実行・リモート画像自動取得も各0件である。
- **SC-503**: 既存の6状態、タイトルのみの Todo、通常メモについて、閲覧・変更・保存・生 Markdown 切替の回帰確認がすべて成功する。サイドパネルと中央エディタ間で競合のない確定済み変更がすべて一致し、パネル専用の複製が0件である。
- **SC-504**: 空メモ・狭いパネル・長文貼り付けを含め、本 User Story の作成・選択・入力・保存・再編集の主要操作をキーボードのみで完了でき、状態・保存結果を色を使わず識別できる。利用確認で各操作後に「何を記録したか」「保存できたか」を確認できることを合格条件とする。

## Assumptions

- 本文の具体的な挙動・既定値は、既存仕様から引き継いだ検証可能な初期案であり、ユーザーによる承認済みの決定ではない。優先順位と実際の提供範囲は003〜006の全ストーリーを比較して決める。
- 要望005の「メモ」は通常メモを指す案とする。サイドパネル専用の一時メモ領域や、003が提供される場合に Todo コメントも必ず同じパネルで編集することまでは要求しない。サイドパネルの複数行入力に006と同じライブ編集方式を採用することも必須ではない。
- 未保存入力は保持するか、切替前に保存・破棄・キャンセルを選択できる案とする。具体的な表示方式は計画段階で決定し、外部編集後の再読込と破損時の復旧を検証する。
- 既存の管理対象ディレクトリ、最初のワークスペースフォルダーを使用する規則、メモの命名、保存・復旧の仕組みを前提とする。共同編集や外部プロセスとの排他制御は追加しない。拡張機能だけで読めるデータ形式を前提にしない。
- 対象外の従来機能は維持する。既存仕様との差分はサイドパネル入力の追加であり、Todo 属性・並び順や002の限定編集は変更せず、チャット機能も追加しない。
- 003〜006で扱う Todo／タスクカードは個人用項目とし、担当者の割り当てや共有ワークフローは導入しない。
