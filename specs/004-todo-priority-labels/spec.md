# Feature Specification: 優先度と独立ラベルで Todo を整理する

**Feature Branch**: `004-todo-priority-labels`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "004：TODOを優先度順にしたい。ラベルとして別途IMPやSKIPなどつけたい。"

**Depends on**: [001 メモ・Todo 管理](../001-memo-todo-management/spec.md)、[002 表示切替・拡張ステータス](../002-note-render-todo-status/spec.md)

**Value**: 着手順を示す優先度と分類ラベルを分けて Todo を整理し、次に対応する作業を一覧から判断できるようにする。

## Clarifications

### Session 2026-09-22
- Q: 1件のTodo/タスクカードに複数コメントがあるとき、一覧ではどの順番で表示しますか? → A: 古いコメント→新しいコメント（手動並び替えは将来的な改善候補）
- Q: 1件のTodo/タスクカードに持てるコメント・詳細は、何件までの仕様にしますか? → A: 複数コメントを持てる（返信機能なし・既存コメント後に追加可）
- Q: 003〜006で扱うTodo/タスクカードは、誰を担当者として割り当てられる仕様にしますか? → A: 担当者は持たない（個人用Todoのまま）
- Q: 完了や Skip などに状態変更した Todo/タスクカードにも、そのままコメントを追加・編集できる仕様にしますか? → A: どの状態でもコメント追加・編集できる

003〜006は機能の識別番号であり、実装順序ではない。Feature Branch は仕様の識別名であり、実ブランチの作成や着手を意味しない。優先順位と実際の提供範囲は、[003](../003-todo-details/spec.md)、[005](../005-side-panel-notes/spec.md)、[006](../006-live-note-editing/spec.md)を含む全ユーザーストーリーを比較して決める。本機能の受入に003・005・006の提供は必要ない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 優先度とラベルを別々に管理する（要望004） (Priority: 未決定)

ユーザーは、着手する順序を優先度で判断し、IMP や SKIP などの分類ラベルを完了状態や優先度とは独立して付けたい。

**Why this priority**: 重要度と分類を混同せずに作業を整理する価値を、他の機能のユーザーストーリーと比較して優先順位と実際の提供範囲を決めるため、未決定とする。

**Independent Test**: コメントがなくても Todo に異なる優先度とラベルを設定でき、並び順と状態の独立性を確認する。003・005・006なしで検証できる。

**Acceptance Scenarios**:

1. **Given** 高・中・低・未設定の Todo が複数ファイルに混在する、**When** 一覧を開く、**Then** 完了以外の認識可能な項目が状態・ファイルをまたいで高→中→低→未設定の順に表示される。完了項目は後述の別グループに表示される。
2. **Given** 同じ優先度の Todo が複数ある、**When** 再読み込みまたは再起動する、**Then** ファイルの相対パス順、同一ファイル内は元の出現順という同じ規則で表示され、元文書の行は並べ替えられない。
3. **Given** 未完了・優先度「低」の Todo がある、**When** IMP と SKIP を付け、さらに任意のラベルを追加する、**Then** 全ラベルを同時に確認でき、状態は未完了、優先度は低のままである。ラベルを外しても状態と優先度は変わらない。
4. **Given** 優先度とラベル付き Todo がある、**When** 完了にしてから未完了に戻す、**Then** 優先度、ラベルが保持され、各一覧内で正しい位置に表示される。003が提供されコメント群がある場合、そのコメント群も保持されるが、コメント群は本シナリオの実施に必須ではない。
5. **Given** 既存の Note・Skip・Warn・IMP 状態の Todo がある、**When** 一覧を開いてラベルや優先度を設定する、**Then** 状態の意味と未解決件数の算出は変わらず、状態が自動でラベルに変換されることもない。
6. **Given** ラベルを編集している、**When** 空白だけの値や既に付いている値を追加する、**Then** 空ラベルや重複は増えず、既存のラベルは維持される。

### Edge Cases

- タイトルだけの旧形式、LF／CRLF、日本語、同名 Todo、末尾改行がない文書を扱っても、対象外の本文や改行形式を変更しない。
- 不明な優先度や未知の記法がある場合は、内容を破棄せず「認識できない Todo」として読み取り専用で示し、生 Markdown での修正へ案内する。003が提供され詳細の所属が曖昧な場合も同様に扱う。
- 優先度変更で表示位置が変わっても、編集対象は元の Todo のままであり、移動先にいた別項目へ入力が適用されない。
- ラベル「SKIP」は既存の状態「Skip」と区別して表示する。ラベルだけの付与は非表示化、完了扱い、未解決件数からの除外を起こさない。
- 外部変更、削除・移動、読み取り専用、保存失敗が起きても、古い内容による上書きや成功表示をせず、入力を退避できる。再起動を伴う場合は終了前に標準の未保存確認または退避手段を提供する。
- ラベルや元の Markdown に未完成の記法や外部コンテンツがあっても、入力を拒否したり外部スクリプトを実行したりせず、安全な表示を継続する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-401**: ユーザーは Todo ごとに「高・中・低・未設定」のいずれかの優先度を設定・変更できなければならない。既存項目と新規項目の既定値は未設定とする。
- **FR-402**: Todo 一覧は、完了以外の認識可能な全項目を状態別に分断せず優先度降順で表示しなければならない。完了項目は後方の初期折りたたみグループ内で同じ順序にする。同順位は相対パスの昇順、同一ファイル内の出現順とし、不明な項目は最後の読み取り専用グループに分離する。表示の並べ替えで保存済み本文を移動してはならない。
- **FR-403**: ユーザーは優先度や状態とは独立して、IMP・SKIP を含む任意の文字列ラベルを複数付与・削除できなければならない。前後の空白を除去し、空値を拒否し、同一表記は重複させない。大文字・小文字は区別する。
- **FR-404**: 状態・優先度・ラベルは一覧で別の属性として判別できなければならない。ラベルの追加・削除は状態、優先度、件数、表示対象を変えてはならず、IMP ラベルから優先度を自動設定してはならない。
- **FR-405**: 001／002の既存 Todo は明示的な変換なしで読み取れ、6状態の選択・変更と未解決件数（未完了・Warn・IMP の合計）を維持しなければならない。旧 IMP 状態を先頭にする表示規則だけは FR-402 の優先度順に置き換える。旧状態をラベルへ自動変換してはならない。
- **FR-406**: 優先度・ラベルも通常の Markdown ファイルに保存し、拡張機能なしでも項目との対応と内容を読んで編集できなければならない。生 Markdown 表示への切替を常に残す。具体的な表記は計画段階で決めるが、既存内容の一括変換を導入条件にしてはならない。
- **FR-407**: 競合時は古い内容を黙って上書きせず、失敗理由と再読込・再試行の案内を示し、未反映の入力をコピーして退避できなければならない。既に未保存の他の編集を意図せず保存・破棄してはならない。
- **FR-408**: 未知の記法や曖昧な Todo は読み取り専用として知らせ、対象外の内容、改行形式、同名の別項目を保持しなければならない。003が提供されている場合はコメント群も保持し、その中のチェックボックスを独立 Todo として二重計上してはならない。状態・優先度・ラベルの変更は、どの状態でも利用できるコメント追加・編集を妨げてはならず、コメントの古い→新しい表示順も保持しなければならない。
- **FR-409**: 新しい操作はキーボードだけで利用でき、状態・優先度・ラベル・保存結果を色だけに依存せず名前で識別できなければならない。日本語 UI と既存の Windows・macOS・Linux 対応を維持する。
- **FR-410**: Markdown 内の外部スクリプトを実行せず、リモート画像を自動取得してはならない。編集・保存は既存の管理対象だけで行い、表示内容により無関係なファイルを変更してはならない。
- **FR-411**: 003〜006で扱う Todo／タスクカードは担当者属性を持たない個人用項目とし、担当者の割り当て・表示・保存・権限制御を本機能で追加してはならない。

### Key Entities

- **Todo**: 所属するメモ、タイトル、既存の状態、優先度、ラベルの集合を持つ個人用の作業項目。同名でも別項目として扱い、担当者属性は持たない。003が提供される場合のコメント群は本仕様では追加しない。
- **優先度**: 着手順を示す「高・中・低・未設定」の単一属性。状態やラベルとは独立する。
- **ラベル**: Todo の分類を示す文字列。1件に複数存在でき、状態遷移や自動処理を意味しない。
- **編集中の入力**: 文書への反映・保存が終わっていない変更。保存状態、競合、退避可能性をユーザーに示す対象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-401**: タイトルのみの旧項目、同名項目、異なる状態を含む10件の Todo で、優先度・複数ラベルを保存して再起動しても、タイトル・状態・優先度・ラベルと所属が全件一致し、対象外の変更が0件である。コメント群は検証の前提にしない。
- **SC-402**: 全4優先度・全6既存状態を含む24件以上の Todo を複数ファイルに用意し、一覧表示・優先度変更・再読み込みのすべてで FR-402 の順序が100%一致する。ラベルだけの変更による状態・件数の変化は0件である。
- **SC-403**: 競合・保存失敗・外部での削除や移動・不明な優先度・並べ替え中の編集を含む境界ケースで、未保存入力の無警告消失と対象外内容の意図しない変更が各0件である。外部スクリプト実行・リモート画像自動取得も各0件である。
- **SC-404**: 既存の6状態、タイトルのみの Todo、通常メモについて、閲覧・変更・保存・生 Markdown 切替の回帰確認がすべて成功する。ただし旧 IMP 先頭順は新しい優先度順への意図した変更として評価する。
- **SC-405**: 本 User Story の優先度設定・変更、ラベル付与・削除の主要操作をキーボードのみで完了でき、状態・優先度・ラベル・保存結果を色を使わず識別できる。利用確認で各操作後に「何を記録したか」「次に対応する項目」「保存できたか」を確認できることを合格条件とする。

## Assumptions

- 本文の具体的な挙動・既定値は、既存仕様から引き継いだ検証可能な初期案であり、ユーザーによる承認済みの決定ではない。優先順位と実際の提供範囲は003〜006の全ストーリーを比較して決める。Todo データの優先度と、機能の提供優先順位は別の概念である。
- 優先度の段階指定がないため「高・中・低・未設定」を初期案とする。高→中→低→未設定、同順位は相対パス・出現順、完了は後方の初期折りたたみグループ、不明な項目は最後という表示も初期案である。手動ドラッグによる任意順、期限、依存関係、通知は本仕様の対象外とする。
- 「別途ラベル」は状態・優先度から独立した複数の文字列ラベルと解釈する。IMP・SKIP は分類名であり自動動作を持たない。空白除去、空値・重複の拒否、大文字・小文字の区別も初期案とする。既存状態の廃止・一括移行は行わず、状態欄とラベル欄の区別で互換性を保つ。
- 既存の管理対象ディレクトリ、最初のワークスペースフォルダーを使用する規則、メモの命名、保存・復旧の仕組みを前提とする。共同編集や外部プロセスとの排他制御は追加しない。
- データの具体的な Markdown 表記と表示方式は計画段階で決定する。その際、既存 Todo との識別、外部編集後の再読込、破損時の復旧を検証する。003が提供されている場合はコメント境界も検証する。拡張機能だけで読めるデータ形式を前提にしない。
- 対象外の従来機能は維持する。既存仕様との差分は優先度・独立ラベルの追加と旧 IMP 先頭表示から優先度順への変更であり、コメント群、サイドパネル入力、連続ライブ編集、別の保存領域やチャット機能は追加しない。
- 003〜006で扱う Todo／タスクカードは個人用項目とし、担当者の割り当てや共有ワークフローは導入しない。
- 003が提供されている場合でも、コメント追加・編集のために完了・Skip などの状態を未完了へ戻すことは要求しない。
- 003が提供されている場合のコメント順は古いコメントから新しいコメントを既定とし、手動並び替えは将来的な改善候補として本機能の受入条件に含めない。
