# Data Model: Todo 中心の統合メモサイドバー

## 統合 Markdown 文書

| 項目 | 内容 |
|------|------|
| 識別 | 管理対象ディレクトリ配下の Markdown ファイル URI |
| 内容 | 通常の Markdown と 0 件以上の Todo |
| 互換性 | 通常 Markdown と現在の Todo 行・拡張ブロック形式を扱う。過去の拡張ブロック形式は互換対象外。未知形式は変更せず読み取り専用にする |
| 更新単位 | 対象 Todo 行と直後に連続する拡張ブロックだけ |

## Todo

| フィールド | 型・制約 | 説明 |
|---|---|---|
| identity | `filePath`, `lineNumber`, `originalText` | ファイルと元の Todo 行で識別する一時参照。同名タイトルでは識別しない。 |
| title | 空でない文字列 | Todo 行のチェックボックス後の本文。 |
| status | `open`, `done`, `note`, `skip`, `warn`, `important`, `unknown` | 既存チェックボックス記法から読む。`unknown` は読み取り専用。 |
| labels | 重複なし文字列集合 | メタデータのカンマ区切りラベル。空値は保存しない。状態・優先度とは独立。 |
| dueDate | `YYYY-MM-DD` または未設定 | 時刻なしの暦日。暦日として無効なら読み取り専用。 |
| bodyMarkdown | 任意の複数行 Markdown | `body` 境界内の本文。 |
| replies | 作成順の `Reply[]` | `comments` 境界内のリプライ。本文の子 Todo としては数えない。 |
| sourceRange | 文書オフセット範囲 | 更新直前に再検証する。保存データではない。 |

## Reply

| フィールド | 型・制約 | 説明 |
|---|---|---|
| id | 親 Todo 内の安定した順序 ID | セッション内で個別編集・削除対象を指定する。 |
| order | 0 からの連番 | 古いものから新しいものへの表示順。手動並び替えはしない。 |
| bodyMarkdown | 空でない複数行 Markdown | 通常 Markdown として保存する。 |
| sourceRange | 文書オフセット範囲 | 個別編集・削除時に対象範囲を再検証する。 |

## WorkspaceLabel

| フィールド | 型・制約 | 説明 |
|---|---|---|
| name | 空でない文字列 | Todo メタデータに保存するラベル名。名前の大文字・小文字は区別する。 |
| color | 固定パレットの識別子 | ワークスペースのリソース設定に保存する。 |

同名ラベルは管理対象 Markdown ファイル全体で同じ `color` を使う。色設定の削除時も Todo のラベル名は
保持し、既定色で表示する。

## Draft

| フィールド | 型・制約 | 説明 |
|---|---|---|
| target | Todo identity と `kind: body \| reply \| attributes`。`reply` の場合だけ Reply ID を持つ | 編集対象を表す。 |
| text | 複数行 Markdown または未設定 | 本文/リプライの未保存入力。属性 draft では使わない。 |
| labels | 属性 draft 中の重複なしラベル文字列集合 | 属性 draft の未保存入力。 |
| dueDate | 属性 draft 中の `YYYY-MM-DD` または未設定 | 属性 draft の未保存入力。 |
| baseVersion | 数値、メモリ内のみ | 編集開始時の文書バージョン。同一 VS Code セッション中の競合検出にだけ使い、再起動後の復元判定には使わない。 |
| baseSource | Todo 元行テキストと編集対象ブロック（本文/Reply/属性）の保存時テキスト | 再起動後の復元先照合と保存時の範囲検証に用いる。 |
| todoIdentity | 文書 URI、Todo 元行、元行テキスト | 再起動後に Todo を探し直すために保存する。同じ元行テキストが複数あり一意に決められない場合は復元せず競合とする。 |
| state | `clean`, `dirty`, `saving`, `conflict`, `failed` | 保存状態を色と文字の両方で示す。 |
| backupKey | ワークスペース URI、文書 URI、Todo identity、編集対象から導くキー | ワークスペース間で分離された一時バックアップファイルの識別に使う。 |
| backupFile | 拡張機能の `globalStorageUri` 配下の JSON ファイル | 永続化可能な draft 情報を保持する。`baseVersion` は永続値として復元判定に使わない。保存完了または明示破棄後に削除する。 |

## Markdown 関係と遷移

```text
Markdown document
└── Todo line
    ├── metadata (0..1)
    ├── body (0..1)
    └── replies (0..n)
```

- Todo 作成時は Todo 行だけでも有効である。
- 本文またはリプライを初めて保存する際に、必要な拡張ブロックだけを Todo 行の直後へ追加する。
- 未保存 draft は `globalStorageUri` 配下へ書き出す。再表示・再起動後の復元時には保存した文書 URI と Todo 元行テキストを使って対象を一意に再特定し、現在の Todo 元行・対象ブロックが永続化した `baseSource` と一致するかを照合する。不一致または複数候補なら競合として保管し、自動適用しない。`baseVersion` は同一セッション中だけ照合する。
- draft のバックアップは保存完了またはユーザーの明示破棄で削除する。対象を失ったバックアップは勝手に破棄せず、復旧または破棄の選択を提示する。
- リプライ削除後にリプライが 0 件になった場合、空のコメント群は削除する。本文・メタデータは維持する。
- Todo 削除は確認後に Todo 行、メタデータ、本文、全リプライを一括で削除する。
- Todo 完了/再開はタイトル、本文、リプライ、ラベル、対応日を変更しない。
- 期限切れは未完了かつ `dueDate` がローカル暦日より前の場合のみ。完了は期限切れではない。

## Validation and read-only conditions

- メタデータは `labels` と `due` だけを受け付ける。ラベルは前後空白を除き、空値・同一表記の重複を除外する。
- 本文、リプライ、コメント境界は Todo 行直後に連続して存在し、開始・終了マーカーが一対でなければならない。
- マーカーの欠落、重複、順序違反、Todo 行から分離したブロック、無効な日付は自動修正せず読み取り専用にする。
- 書き込み前に URI の管理対象性、ファイル書込み可否、文書バージョン、元範囲、ディスク一致を検証する。
