# Feature Specification: ビュー起動と空表示からの作成

**Feature Branch**: `008-view-provider-empty-state`

**Created**: 2026-09-27

**Status**: Draft

**Input**: User description: "008。このエラーが出ないように対策しよう。何もないときは新規作成できるようにもして"

## Clarifications

### Session 2026-09-27
- Q: データが空のとき、メモや Todo の新規作成操作をどこから直接始められるようにしますか？ → A: メモ一覧・Todo一覧・統合ビューの空状態すべてに、それぞれの新規作成操作を表示する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - QuickNoteMD のビューを確実に開く (Priority: P1)

QuickNoteMD を有効にしているユーザーは、アクティビティバーからメモや Todo のビューを開き、データの有無にかかわらず一覧を利用できる。「ビュー データを提供できるデータ プロバイダーが登録されていません」というエラーで利用を妨げられない。

**Why this priority**: ビューを開けなければ、既存データの閲覧も作成もできないため。

**Independent Test**: QuickNoteMD を有効にし、ワークスペースを開いた状態で、初回起動時とウィンドウ再読み込み後に各 QuickNoteMD ビューを開く。エラーが出ず、一覧または適切な空状態が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** QuickNoteMD が有効でワークスペースが開いている、**When** ユーザーがアクティビティバーからメモ、Todo、または統合ビューを開く、**Then** ビューがエラーなく表示され、登録不足を示すメッセージが表示されない。
2. **Given** VS Code を起動またはウィンドウを再読み込みした直後である、**When** ユーザーが QuickNoteMD のビューを初めて開く、**Then** 初回からビューを利用できる。
3. **Given** QuickNoteMD が有効だがワークスペースが開かれていない、**When** ユーザーが QuickNoteMD の操作を試みる、**Then** 利用できない理由と必要な対応が案内され、空の一覧や成功したかのような表示に見せかけない。

---

### User Story 2 - 空の一覧からメモや Todo を作成する (Priority: P1)

管理対象のメモまたは Todo がまだないユーザーは、一覧の空状態から作成を始められる。作成のためにコマンド名を調べたり、別の画面に移動したりする必要がない。

**Why this priority**: 初回利用時に一覧が空でも、次に何をすればよいか分かり、その場で主要な機能を試せるようにするため。

**Independent Test**: 空のメモ一覧と空の Todo 一覧をそれぞれ表示し、空状態に示された操作から1件ずつ作成する。作成した項目が通常の一覧に表示され、閉じて再度開いた後も利用できることを確認する。

**Acceptance Scenarios**:

1. **Given** 管理対象の Markdown メモが1件もない、**When** ユーザーがメモ一覧の空状態を確認する、**Then** 新しいメモを作成する操作が表示され、その場から作成を開始できる。
2. **Given** Todo が1件もない、**When** ユーザーが Todo 一覧の空状態を確認する、**Then** 新しい Todo を作成する操作が表示され、その場から作成を開始できる。
3. **Given** 統合ビューにメモも Todo もない、**When** ユーザーが空状態を確認する、**Then** メモと Todo の新規作成操作が表示され、それぞれの作成をその場から開始できる。
4. **Given** メモまたは Todo を空状態から作成した、**When** 作成が完了する、**Then** 既存の保存先と形式に従って保存され、一覧が更新される。
5. **Given** 作成操作で入力をキャンセルした、**When** ユーザーが入力を閉じる、**Then** 空状態のままで、空の項目や不完全なファイルは作られない。

### Edge Cases

- 保存先のワークスペースが開かれていない、読み取り専用、または書き込み不可の場合、空状態と保存失敗を混同せず、次に取れる対応を案内する。
- 一覧の読み込みに失敗した場合、作成を促す空状態として扱わず、読み込みに失敗したことをユーザーに知らせる。
- 初回起動とウィンドウ再読み込み直後のいずれでも、ビューごとに異なる起動タイミングによってエラー表示や空状態が不安定にならない。
- メモのみ存在する場合、Todo のみ存在する場合、または一方の作成に失敗した場合も、他方のビューは利用でき、状態を正しく表示する。
- 空状態の作成操作はキーボードとスクリーンリーダーで識別・実行できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: QuickNoteMD が有効で対応するワークスペースが開かれている場合、ユーザーが提供対象のいずれかの QuickNoteMD ビューを開いたとき、ビューがデータ提供者の未登録を示すエラーなしに利用可能にならなければならない。
- **FR-002**: 初回起動およびウィンドウ再読み込み後の初回表示でも、各ビューは開く操作に応じて利用可能にならなければならない。
- **FR-003**: 管理対象メモがないとき、メモ一覧は新しいメモを作成する明確な操作を表示し、その場から作成を開始できなければならない。
- **FR-004**: Todo がないとき、Todo 一覧は新しい Todo を作成する明確な操作を表示し、その場から作成を開始できなければならない。
- **FR-005**: 空状態から作成されたメモと Todo は、それぞれ既存の保存先、命名規則、Markdown 形式を使用し、成功後に該当する一覧へ反映されなければならない。
- **FR-006**: ユーザーが作成をキャンセルした場合、空の項目または不完全なファイルを作成してはならない。
- **FR-007**: QuickNoteMD が有効でもワークスペースがない、または保存先を読み込めない状態を、正常な空状態と混同してはならない。状況に応じた説明と利用可能な次の手順を示さなければならない。
- **FR-008**: 空状態の操作はキーボードで実行でき、アクセシビリティ支援機能で操作名と目的を判別できなければならない。
- **FR-009**: メモ一覧、Todo 一覧、および統合ビューの空状態には、それぞれのビューからメモまたは Todo の新規作成を直接開始できる操作を表示しなければならない。

### Key Entities

- **メモ**: 既存の保存先と命名規則に従って作成・表示される Markdown 文書。
- **Todo**: 既存の Todo 保存規則に従って作成・表示される項目。
- **ビュー状態**: 利用可能、データなし、または読み込み・利用に問題がある状態。ユーザーが次の操作を判断できるよう区別される。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: QuickNoteMD が有効でワークスペースが開いている状態で、初回起動およびウィンドウ再読み込み後に各ビューを開く試行の100%で、データ提供者未登録エラーが表示されない。
- **SC-002**: メモも Todo もない状態から、ユーザーはそれぞれの一覧内の案内に従い、1分以内に最初のメモまたは Todo の作成を開始できる。
- **SC-003**: 空状態からのメモ作成と Todo 作成を各10回試したとき、入力を確定した全項目が通常の一覧に表示され、キャンセルした操作から生成される空項目は0件である。
- **SC-004**: データ読込失敗、ワークスペース未選択、保存不可の各状態で、ユーザーが通常の空状態と区別できる案内が100%表示される。
- **SC-005**: 空状態からの作成操作を、キーボードのみで開始して完了できる。

## Assumptions

- QuickNoteMD の「何もないとき」は、ワークスペースが開かれているが、管理対象のメモまたは Todo がまだ存在しない状態を指す。
- データは引き続き既存の管理対象ディレクトリと Markdown 形式に保存する。ユーザー領域への保存や、既存の保存先規則の変更は対象外とする。
- ワークスペースが開かれていない場合は作成先を推測せず、ワークスペースを開くよう案内する。
- 対応する VS Code と QuickNoteMD が有効であることを前提とする。無効化された拡張機能のビューを利用可能にすることは対象外とする。
- 既存のコマンドやビュー上の作成操作は維持し、空状態からの作成導線を追加する。
