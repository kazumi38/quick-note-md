# Feature Specification: Todo 詳細メモ・優先度・サイドパネル入力・連続ライブ編集

**Feature Branch**: `copilot/speckit-specify-todo-improvements`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "003：TODOはタイトルだけでなく、メモをとれるようにしてほしい。タイトルだけじゃなくて、課題やどのように対応するかなどもメモするため。004：TODOを優先度順にしたい。ラベルとして別途IMPやSKIPなどつけたい。005：サイドパネル上でもメモをとりたい。006：プレビューの画面の編集は改行ごとじゃないようにしてほしい（TeamsやGPTのように自動レンダリングしながら記入できるようにしたい。）"

**Depends on**: [001 メモ・Todo 管理](../001-memo-todo-management/spec.md)、[002 表示切替・拡張ステータス](../002-note-render-todo-status/spec.md)

要望番号003〜006を追跡可能な4つの利用シナリオとして、今回の1仕様にまとめる。個別の004〜006仕様を作成したことを意味しない。既存の管理対象メモと Todo を拡張し、別の保存領域やチャット機能を追加するものではない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Todo に課題と対応方針を残す（要望003） (Priority: P1)

ユーザーは、Todo の短いタイトルとは別に、課題の背景、調査内容、対応方針や進捗を複数行で記録し、後から読み返して追記・修正したい。

**Why this priority**: タイトルだけでは残せない作業の文脈を保持し、Todo を再開するときの情報不足を解消する。

**Independent Test**: タイトルのみの既存 Todo を開き、課題と対応方針を複数段落で追記して保存し、再度開いて確認する。優先度、サイドパネル編集、ライブ編集が未提供でも検証できる。

**Acceptance Scenarios**:

1. **Given** タイトルのみの Todo がある、**When** その項目の詳細メモを開く、**Then** タイトルと空の詳細メモが区別され、既存内容は変更されない。
2. **Given** Todo の詳細を編集している、**When** 課題と対応方針を見出し・段落・箇条書きで入力して保存する、**Then** 再表示・再起動後も同じ Todo に結び付いた内容として読める。
3. **Given** 詳細メモ付き Todo がある、**When** タイトルまたは状態を変更する、**Then** 詳細メモは保持される。詳細メモのみの修正・消去ではタイトル、状態、他の Todo は変わらない。
4. **Given** 同名の Todo が同一ファイルと別ファイルに存在する、**When** 1件の詳細メモを変更する、**Then** 選択した1件だけが変更される。
5. **Given** 詳細メモ付き Todo がある、**When** 削除を要求する、**Then** 詳細メモも削除対象であると明示され、キャンセルすれば両方が残り、承認すれば対象 Todo とその詳細だけが削除される。

### User Story 2 - 優先度とラベルを別々に管理する（要望004） (Priority: P1)

ユーザーは、着手する順序を優先度で判断し、IMP や SKIP などの分類ラベルを完了状態や優先度とは独立して付けたい。

**Why this priority**: 重要度と分類を混同せず、次に対応する Todo を一覧から判断できるようにする。

**Independent Test**: 詳細メモのない Todo に異なる優先度とラベルを設定し、並び順と状態の独立性を確認する。

**Acceptance Scenarios**:

1. **Given** 高・中・低・未設定の Todo が複数ファイルに混在する、**When** 一覧を開く、**Then** 完了以外の認識可能な項目が状態・ファイルをまたいで高→中→低→未設定の順に表示される。完了項目は後述の別グループに表示される。
2. **Given** 同じ優先度の Todo が複数ある、**When** 再読み込みまたは再起動する、**Then** ファイルの相対パス順、同一ファイル内は元の出現順という同じ規則で表示され、元文書の行は並べ替えられない。
3. **Given** 未完了・優先度「低」の Todo がある、**When** IMP と SKIP を付け、さらに任意のラベルを追加する、**Then** 全ラベルを同時に確認でき、状態は未完了、優先度は低のままである。ラベルを外しても状態と優先度は変わらない。
4. **Given** 優先度とラベル付き Todo がある、**When** 完了にしてから未完了に戻す、**Then** 優先度、ラベル、詳細メモが保持され、各一覧内で正しい位置に表示される。
5. **Given** 既存の Note・Skip・Warn・IMP 状態の Todo がある、**When** 一覧を開いてラベルや優先度を設定する、**Then** 状態の意味と未解決件数の算出は変わらず、状態が自動でラベルに変換されることもない。
6. **Given** ラベルを編集している、**When** 空白だけの値や既に付いている値を追加する、**Then** 空ラベルや重複は増えず、既存のラベルは維持される。

### User Story 3 - サイドパネルでメモを書く（要望005） (Priority: P2)

ユーザーは、作業中のコードや文書を中央エディタに表示したまま、QuickNoteMD のサイドパネル内でメモを新規作成し、既存メモを開いて追記・修正したい。

**Why this priority**: 作業対象から離れずに記録できるが、Todo の詳細や優先順位の管理とは独立して提供できる。

**Independent Test**: 中央エディタに任意のファイルを表示したまま、サイドパネル内だけでメモの作成・本文入力・保存・再編集を完了する。

**Acceptance Scenarios**:

1. **Given** 中央エディタで作業中である、**When** サイドパネルで新規メモのタイトルと複数行の本文を入力して保存する、**Then** 中央エディタの表示対象を変えずに、通常のメモ一覧から再び開けるメモが作成される。
2. **Given** 既存メモがある、**When** サイドパネル内で選択して既存本文の修正と追記を行い保存する、**Then** 同じメモに反映され、サイドパネル専用の複製は作られない。
3. **Given** サイドパネルに未保存または未反映の入力がある、**When** 別メモへの切替やパネルの非表示・再表示を行う、**Then** 入力が保持されるか、切替前に保存・破棄・キャンセルを選択でき、黙って消失しない。
4. **Given** 同じメモを中央エディタにも開いている、**When** 一方で変更する、**Then** 競合のない確定済み変更は他方でも確認でき、競合時は未保存の入力を上書きせず警告される。
5. **Given** 保存先が使用不能である、**When** サイドパネルで保存を試みる、**Then** 保存失敗と復旧方法が表示され、入力をコピーして退避できる。

### User Story 4 - 改行で編集を中断しないライブ編集（要望006） (Priority: P1)

ユーザーは、メモのレンダリング画面で、行ごとに編集箇所を開いたり確定したりせず、文章を連続して入力したい。入力した見出しや強調などの結果を、別画面に移らずその場で確認したい。

**Why this priority**: 現在の行・ブロック単位の編集では長い文章の作成が分断されるため、主要な入力体験として改善する。

**Independent Test**: 通常メモのレンダリング画面で複数段落を連続入力し、改行、段落をまたぐ選択・置換、貼り付け、Undo／Redo を実行する。Todo 拡張やサイドパネル入力に依存しない。

**Acceptance Scenarios**:

1. **Given** 空のメモまたは既存の段落を編集している、**When** Enter を含めて複数段落を連続入力する、**Then** Enter は改行または段落の作成として働き、編集終了・送信・次の行の編集開始操作を要求しない。
2. **Given** 複数段落を編集している、**When** 段落境界をまたいで選択・置換・削除し、複数行を貼り付ける、**Then** 一続きの編集として操作でき、選択範囲外の内容は変わらない。
3. **Given** 見出し・強調・通常の箇条書きを入力している、**When** 表示可能な記法まで入力する、**Then** 保存・改行・フォーカス移動を待たずに同じ編集面で整形結果を確認でき、入力位置や選択が別の場所に飛ばない。
4. **Given** 日本語を変換入力している、**When** 変換候補の選択と確定を行う、**Then** 自動表示更新が変換を中断せず、文字の欠落・重複や意図しない改行が生じない。
5. **Given** 複数段落の変更を行った、**When** Undo／Redo、保存、生 Markdown 表示への切替、再表示を行う、**Then** 変更を取り消し・再適用でき、最終的な本文と Markdown の意味が一致する。
6. **Given** テーブルやコードブロックなど直接編集の対象外の構造を含む、**When** 周辺の文章を編集する、**Then** 対象外の内容は保持される。その構造自体またはそれをまたぐ範囲を編集しようとした場合は、生 Markdown での編集へ案内され、変更は黙って適用されない。

### Edge Cases

- 詳細メモ中の空行、見出し、箇条書き、チェックボックス風の文章と隣接 Todo の境界を取り違えない。詳細内のチェックボックスは本機能では独立した Todo として一覧・件数に含めない。
- タイトルだけの旧形式、LF／CRLF、日本語、同名 Todo、末尾改行がない文書を扱っても、対象外の本文や改行形式を変更しない。
- 不明な優先度や曖昧な詳細の所属がある場合は、内容を破棄せず「認識できない Todo」として読み取り専用で示し、生 Markdown での修正へ案内する。
- 優先度変更で表示位置が変わっても、編集対象は元の Todo のままであり、移動先にいた別項目へ入力が適用されない。
- ラベル「SKIP」は既存の状態「Skip」と区別して表示する。ラベルだけの付与は非表示化、完了扱い、未解決件数からの除外を起こさない。
- 空のメモ、狭いサイドパネル、長文貼り付けでも、入力欄と保存状態をキーボードで確認・操作できる。
- 外部変更、削除・移動、読み取り専用、保存失敗が起きても、古い内容による上書きや成功表示をせず、入力を退避できる。再起動を伴う場合は終了前に標準の未保存確認または退避手段を提供する。
- レンダリング中に未完成の Markdown や外部コンテンツを含んでも、入力を拒否したり外部スクリプトを実行したりせず、安全な表示を継続する。

## Requirements *(mandatory)*

### Functional Requirements

#### Todo の詳細メモ

- **FR-301**: 各 Todo は必須のタイトルと任意の複数行詳細メモを持ち、ユーザーは両者を区別して閲覧・編集できなければならない。タイトルのみでの作成も継続して利用できる。
- **FR-302**: 詳細メモは段落、見出し、箇条書き、リンクを含む Markdown として記録でき、保存・再表示・再起動後も対象 Todo との対応を保持しなければならない。
- **FR-303**: 詳細の変更は当該 Todo の詳細だけに適用し、タイトル・状態・優先度・ラベルや隣接項目を変更してはならない。他の属性の変更も詳細を失わせてはならない。
- **FR-304**: Todo の削除時は詳細も削除することを確認し、キャンセル時は何も変更してはならない。詳細の所属が曖昧な場合は削除せず警告する。

#### 優先度と独立ラベル

- **FR-305**: ユーザーは Todo ごとに「高・中・低・未設定」のいずれかの優先度を設定・変更できなければならない。既存項目と新規項目の既定値は未設定とする。
- **FR-306**: Todo 一覧は、完了以外の認識可能な全項目を状態別に分断せず優先度降順で表示しなければならない。完了項目は後方の初期折りたたみグループ内で同じ順序にする。同順位は相対パスの昇順、同一ファイル内の出現順とし、不明な項目は最後の読み取り専用グループに分離する。表示の並べ替えで保存済み本文を移動してはならない。
- **FR-307**: ユーザーは優先度や状態とは独立して、IMP・SKIP を含む任意の文字列ラベルを複数付与・削除できなければならない。前後の空白を除去し、空値を拒否し、同一表記は重複させない。大文字・小文字は区別する。
- **FR-308**: 状態・優先度・ラベルは一覧で別の属性として判別できなければならない。ラベルの追加・削除は状態、優先度、件数、表示対象を変えてはならず、IMP ラベルから優先度を自動設定してはならない。
- **FR-309**: 001／002 の既存 Todo は明示的な変換なしで読み取れ、6状態の選択・変更と未解決件数（未完了・Warn・IMP の合計）を維持しなければならない。旧 IMP 状態を先頭にする表示規則だけは FR-306 の優先度順に置き換える。旧状態をラベルへ自動変換してはならない。

#### サイドパネルでのメモ入力

- **FR-310**: QuickNoteMD のサイドパネル内で、通常メモの新規作成、既存メモの選択、複数行の本文の閲覧・追記・修正・保存を完結できなければならない。中央エディタへ移動することを必須にしてはならない。
- **FR-311**: サイドパネルと中央エディタは同じメモを扱い、競合のない確定済み変更を相互に反映しなければならない。新規メモは既存の管理対象・命名規則に従い、通常のメモ一覧に表示する。
- **FR-312**: 保存済み・未保存・保存失敗を区別して表示し、メモ切替、パネル非表示、表示モード変更で未保存入力を黙って破棄してはならない。

#### 連続ライブ編集

- **FR-313**: メモのレンダリング画面は、段落・見出し・通常の箇条書きを一続きに編集でき、Enter、複数行の貼り付け、段落をまたぐ選択・削除・置換を提供しなければならない。行または段落ごとの編集開始・確定操作を要求してはならない。
- **FR-314**: 入力に応じた整形結果を同じ編集面に自動反映しなければならない。保存・改行・フォーカス移動や別プレビューの再読込を反映条件にしてはならない。未完成の記法は入力を保持してテキストとして扱ってよい。
- **FR-315**: 自動反映は、キャレット、選択範囲、日本語の変換中入力を妨げてはならない。通常の保存と Undo／Redo を利用でき、表示切替によって未保存の編集履歴を失ってはならない。
- **FR-316**: 直接編集の対象外の構造は保護し、その構造を含む編集には生 Markdown への切替手段と理由を示さなければならない。周辺の対応済み文章の連続編集は妨げず、対象外の記法を黙って書き換えてはならない。

#### 共通の保護と互換性

- **FR-317**: 詳細メモ・優先度・ラベルも通常の Markdown ファイルに保存し、拡張機能なしでも項目との対応と内容を読んで編集できなければならない。生 Markdown 表示への切替を常に残す。具体的な表記は計画段階で決めるが、既存内容の一括変換を導入条件にしてはならない。
- **FR-318**: 競合時は古い内容を黙って上書きせず、失敗理由と再読込・再試行の案内を示し、未反映の入力をコピーして退避できなければならない。既に未保存の他の編集を意図せず保存・破棄してはならない。
- **FR-319**: 未知の記法や曖昧な Todo は読み取り専用として知らせ、対象外の内容、改行形式、同名の別項目を保持しなければならない。詳細メモ内のチェックボックスを独立 Todo として二重計上してはならない。
- **FR-320**: 新しい操作はキーボードだけで利用でき、状態・優先度・ラベル・保存結果を色だけに依存せず名前で識別できなければならない。日本語 UI と既存の Windows・macOS・Linux 対応を維持する。
- **FR-321**: Markdown 内の外部スクリプトを実行せず、リモート画像を自動取得してはならない。編集・保存は既存の管理対象だけで行い、表示内容により無関係なファイルを変更してはならない。

### Key Entities

- **Todo**: 所属するメモ、タイトル、状態、詳細メモ、優先度、ラベルの集合を持つ作業項目。同名でも別項目として扱う。
- **詳細メモ**: 1件の Todo に属する任意の複数行 Markdown。課題、対応方針、進捗を自由に記録する。
- **優先度**: 着手順を示す「高・中・低・未設定」の単一属性。状態やラベルとは独立する。
- **ラベル**: Todo の分類を示す文字列。1件に複数存在でき、状態遷移や自動処理を意味しない。
- **通常メモ**: サイドパネルと中央エディタから同じ内容を閲覧・編集する Markdown 文書。
- **編集中の入力**: 文書への反映・保存が終わっていない変更。保存状態、競合、退避可能性をユーザーに示す対象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-301**: タイトルのみ、複数段落、同名項目、異なる状態を含む10件の Todo で、詳細・優先度・複数ラベルを保存して再起動しても、属性と所属が全件一致し、対象外の変更が0件である。
- **SC-302**: 全4優先度・全6既存状態を含む24件以上の Todo を複数ファイルに用意し、一覧表示・優先度変更・再読み込みのすべてで FR-306 の順序が100%一致する。ラベルだけの変更による状態・件数の変化は0件である。
- **SC-303**: 中央エディタの表示対象を変える操作0回で、サイドパネルからメモの新規作成、3段落の記入、保存、既存本文の修正を完了できる。
- **SC-304**: 10段落の連続入力・段落をまたぐ置換・複数行貼り付けを、行ごとの編集開始／確定操作0回で完了でき、日本語変換を含め入力の欠落・重複が0件である。
- **SC-305**: 1,000行以内のメモにおける100回の表示可能な記法の入力で、95回以上は入力後500ミリ秒以内に同じ編集面で整形結果を確認できる。変換中の日本語は変換確定後から測定する。
- **SC-306**: 競合・保存失敗・パネル切替・対象外構造を含む境界ケースで、未保存入力の無警告消失と対象外内容の意図しない変更が0件である。
- **SC-307**: 既存の6状態、タイトルのみの Todo、通常メモについて、閲覧・変更・保存・生 Markdown 切替の回帰確認がすべて成功する。ただし旧 IMP 先頭順は新しい優先度順への意図した変更として評価する。
- **SC-308**: 各 User Story の主要操作をキーボードのみで完了でき、状態・優先度・ラベル・保存結果を色を使わず識別できる。利用確認で各操作後に「何を記録したか」「次に対応する項目」「保存できたか」を確認できることを合格条件とする。

## Assumptions

- 要望003〜006は要望の識別番号として保持し、今回の `/speckit-specify` では1つの機能仕様とする。4つの利用シナリオは独立して受入確認できる。
- 優先度の段階指定がないため「高・中・低・未設定」を初期案とする。手動ドラッグによる任意順、期限、依存関係、通知は今回の対象外とする。
- 「別途ラベル」は状態・優先度から独立した複数の文字列ラベルと解釈する。IMP・SKIP は分類名であり自動動作を持たない。既存状態の廃止・一括移行は行わず、状態欄とラベル欄の区別で互換性を保つ。
- 要望005の「メモ」は通常メモを指す。サイドパネル専用の一時メモ領域や、Todo 詳細も必ず同じパネルで編集することまでは要求しない。サイドパネルの複数行入力に要望006と同じライブ編集方式を採用することも必須ではない。
- Teams／GPT は途切れない入力体験の参考であり、チャット、送信、AI 生成、外部サービス連携を求めるものではない。
- 要望006は002の行・ブロック単位の限定編集を置き換える。今回の連続直接編集は段落・見出し・通常の箇条書きが対象で、テーブル、コードブロック、画像、複雑なネストの直接編集や任意のリッチテキスト機能は対象外とする。通常の改行や対応する段落間の編集を対象外として扱ってはならない。
- 既存の管理対象ディレクトリ、最初のワークスペースフォルダーを使用する規則、メモの命名、保存・復旧の仕組みを前提とする。共同編集や外部プロセスとの排他制御は追加しない。
- データの具体的な Markdown 表記と表示方式は `/speckit-plan` で決定する。その際、詳細の境界、既存 Todo との識別、外部編集後の再読込、破損時の復旧を検証する。拡張機能だけで読めるデータ形式を前提にしない。
- 対象外の従来機能は維持する。既存仕様との差分は、Todo 属性の追加、旧 IMP 先頭表示から優先度順への変更、サイドパネル入力の追加、002の限定編集から連続編集への拡張である。
