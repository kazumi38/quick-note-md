## Clarifications

### Session 2026-10-04

- Q: チャットの Markdown ファイルを VS Code の原文エディタで変更し、まだ保存していない場合、チャット表示にもその変更を反映しますか? → A: 未保存の原文変更を一覧タイトル・スレッドに反映し、「原文に未保存の変更あり」と表示する。原文の保存または破棄が済むまで送信を停止し、他の編集を勝手に保存しない。
- Q: 入力とリアルタイムの整形表示はどこで行いますか? → A: 入力欄そのものを入力中にレンダリングする。別枠のリアルタイムプレビューは不要であり、入力した場所で整形結果を直接編集する。
- Q: INFO／WARN等はどの形式で表示しますか? → A: 既存の状態付き項目（`- [ ]`、`- [x]`、`- [i]`、`- [!]`、`- [n]`、`- [-]`）と、注意書きブロック（`> [!INFO]`、`> [!WARN]`）の両方を、入力欄内と送信済みメッセージで表示する。
- Q: チェック項目のチェックボックスは、どこでクリックして状態を切り替えられるようにしますか? → A: 入力欄と送信済みメッセージの両方で未完了／完了を切り替えられる。送信済み側は対象ファイルを安全に更新する。
- Q: 整形された見出し・箇条書き・注意書きの末尾でEnterを押したとき、次の行をどう扱いますか? → A: 見出しから通常段落へ戻る。リストは次項目へ進み、未完了／完了チェックの次項目は未完了で開始する。注意書きは内部で改行する。空項目・空行のEnterで書式から退出し、Shift+Enterは同じ書式内で改行する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 送信せずに入力結果をチャット内で確認する (Priority: P1)

ユーザーは本文・返信を途切れずに Markdown で入力し、入力欄そのものがリアルタイムに整形される状態で、文章を直接編集したい。別枠のプレビューは設けず、入力した場所で見出し・強調・リスト等を確認する。保存、送信、画面切替は確認の前提にしない。

**Why this priority**: 中心機能は入力した場所での描画である。保存後の表示、手動更新、入力欄と別のプレビューを見比べる方式では本機能の価値を満たさない。

**Independent Test**: 未送信の本文または返信に見出し、強調、箇条書き、コードを連続入力し、入力途中の描画と保存先ファイルが未変更であることを確認する。

**Acceptance Scenarios**:

1. **Given** 本文または返信の入力欄が空である、**When** `# 確認事項`、`**ログイン画面**について確認してください。`、デザイン・API・エラー処理の箇条書きを入力する、**Then** 入力欄そのものに見出し、強調、リストが自動描画され、その表示を直接編集できる。別枠のプレビューも送信操作も要求しない。
2. **Given** 描画結果が表示されている、**When** 文字を追加・削除・置換し、貼り付け、Undo／Redo を行う、**Then** 最新の入力内容に自動追従し、古い内容へ戻ったり別のチャットの内容を表示したりしない。
3. **Given** 日本語の変換入力または複数行の入力を行っている、**When** Enter、変換確定、カーソル移動を行う、**Then** 入力・選択を妨げず、Enter は送信ではなく改行となり、確定後の日本語も自動描画される。
4. **Given** 未完成の強調、リスト、コード囲みを入力している、**When** 記法を完成させる、**Then** 未完成の間も入力を保持し、安全な表示から完成後の整形結果へ自動更新する。
5. **Given** 未送信の本文または返信を入力している、**When** 入力欄の整形結果が更新される、**Then** チャットの Markdown ファイルへの確定保存は行われない。
6. **Given** 強調や見出しとして整形された文章を入力欄で編集している、**When** 文中へカーソルを移し、選択・置換・改行・Undo／Redoを行う、**Then** 同じ入力欄で編集が続き、内容と整形の意味を保持する。自動描画がカーソルを末尾へ飛ばしてはならない。
7. **Given** 見出し・リスト・チェック項目・注意書きの末尾で入力している、**When** Enterを押す、**Then** 見出しは通常段落へ、リストは次項目へ、チェック項目は未完了の次項目へ、注意書きは内部の次行へ進む。空項目・空行のEnterでその書式から退出でき、送信されない。
8. **Given** 見出し・リスト項目・注意書きの中で入力している、**When** Shift+Enterを押す、**Then** 同じ書式内に改行を挿入して入力を継続し、送信されない。

### User Story 2 - チャットを選び、保存済みの会話を読む (Priority: P1)

ユーザーはサイドパネルのチャット一覧からスレッドを選び、タイトル、本文、返信、各メッセージの日時を、Markdown 記法ではなく読みやすいチャットとして閲覧したい。

**Why this priority**: 入力中のメッセージを既存の会話の中で確認できることが、単なる Markdown エディタとプレビューとの差になる。

**Independent Test**: 3つのチャットファイルを用意して一覧から切り替え、各ファイルのタイトル、セクション、メッセージ、整形結果を確認する。

**Acceptance Scenarios**:

1. **Given** 管理対象に複数のチャットファイルがある、**When** サイドパネルを開く、**Then** チャット一覧と「新しいチャット」が表示され、旧 Todo／メモの分類・操作 UI は表示されない。
2. **Given** チャット一覧がある、**When** 項目を選択する、**Then** 対応する1ファイルのスレッドだけを表示し、選択中のチャットを識別できる。
3. **Given** `# ログイン画面について`、`## 本文`、`## 返信` と、日時を表す3つの `###` メッセージ見出しを持つファイルがある、**When** 開く、**Then** タイトル、2セクション、3メッセージをファイル内の順序で表示する。
4. **Given** メッセージに強調、リスト、コード、表がある、**When** スレッドを表示する、**Then** メッセージ本文全体が整形され、構造用の見出しを本文に重複表示しない。
5. **Given** 管理対象にチャットがない、**When** サイドパネルを開く、**Then** 空状態と作成操作を表示する。ワークスペースがない場合は必要な操作を案内する。
6. **Given** 入力欄または送信済みメッセージに未完了／完了のチェック項目がある、**When** クリックまたはキーボードでチェックを切り替える、**Then** 入力欄では下書きだけを変更し、送信済み側ではその項目の状態だけをファイルへ保存する。保存後の再読込でも状態が一致する。
7. **Given** 送信済みのチェック項目に未保存の原文変更、競合、読み取り専用、保存失敗がある、**When** 状態を切り替えようとする、**Then** 安全な保存ができなければ停止して理由を示し、保存済み状態を成功したかのように表示せず、既存本文と返信下書きを保持する。

### User Story 3 - 本文・返信を送信し、ファイルとして残す (Priority: P1)

ユーザーは新しいチャットにタイトルと本文を入力するか、既存のチャットへ返信し、整形結果を確認してから送信したい。保存した会話は通常の Markdown として他のエディタでも読める必要がある。

**Why this priority**: 入力、即時描画、確認、送信、ファイル保存という一連の体験を完成させるために必要である。

**Independent Test**: 新しいチャットの本文と2返信を送信し、対応ファイルが1つだけ作成され、再読込後も同じ会話を表示することを確認する。

**Acceptance Scenarios**:

1. **Given** 新しいチャットのタイトルと本文を入力している、**When** 入力欄内の整形結果を確認して送信する、**Then** タイトル、本文セクション、日時付きの本文メッセージを持つ1つの Markdown ファイルを作成し、一覧に反映して選択する。
2. **Given** 既存のチャットで返信を入力している、**When** 送信する、**Then** 同じファイルの返信セクション末尾へ日時付きメッセージを1件追加する。返信セクションがなければ作成し、既存の本文・返信を保持する。
3. **Given** 保存済みのチャットを閉じた、**When** 再度開く、**Then** タイトル、セクション、メッセージ数・順序、Markdown の意味が保存前と一致する。
4. **Given** 本文に通常の `#`・`##`・`###` 見出し、引用、コード内の見出し風の文字列がある、**When** 送信し再読込する、**Then** 本文内の見出しは元の見た目で表示され、追加のチャット・セクション・メッセージとして誤認されない。
5. **Given** タイトルまたは本文が空白だけ、あるいは送信処理が進行中である、**When** 送信操作を行う、**Then** 空メッセージや重複メッセージを保存せず、必要な入力または処理中の状態を知らせる。

### User Story 4 - 外部編集と保存失敗でも入力を失わない (Priority: P2)

ユーザーは Markdown を直接編集でき、変更後の一覧とスレッドを確認したい。外部変更や保存失敗が起きても、下書きや既存の内容を黙って失いたくない。

**Why this priority**: ローカルファイルをデータの原本とする既存の運用と、データ所有権を維持するために必要である。

**Independent Test**: 選択中のチャットを外部編集・削除し、読み取り専用で送信する。更新通知、競合時の停止、下書きの回収を確認する。

**Acceptance Scenarios**:

1. **Given** 保存済みチャットを表示している、**When** ファイルを直接変更・作成・削除・移動する、**Then** 既存の変更検知に合わせて一覧とスレッドを更新し、消失したファイルの古い内容を現在の状態として表示しない。
2. **Given** 下書きがある、**When** チャットを切り替え、一覧が更新され、パネルを閉じて再表示する、**Then** 下書きが別チャットへ混ざったり黙って失われたりしない。
3. **Given** 外部変更、他の未保存編集、読み取り専用、保存失敗がある、**When** 送信する、**Then** 安全な保存を確認できない場合は理由と再読込・再試行・入力退避の手段を示し、成功扱いにせず、下書きを保持する。
4. **Given** 構造が不正またはチャット形式ではない既存ファイルがある、**When** 一覧またはスレッドを表示する、**Then** 対応できない理由と元の Markdown を開く手段を示し、無断の変換・追記・削除を行わない。
5. **Given** チャットの原文を VS Code で編集している、**When** 未保存のままタイトルや本文を変更する、**Then** 一覧タイトル・スレッドに変更を反映し、「原文に未保存の変更あり」と明示する。チャットの下書きは保持し、原文の保存または破棄が済むまで送信を停止する。
6. **Given** 未保存の原文変更により送信が停止している、**When** ユーザーが原文を保存または破棄する、**Then** 一覧タイトル・スレッドと未保存表示を更新する。下書きの保存元と最新内容が異なる場合は競合として確認を求め、同じ場合は送信できる状態へ戻す。

### User Story 5 - 狭いサイドパネルでも安全に操作する (Priority: P2)

ユーザーは狭い幅でも長い日本語やコードを読み、キーボードだけでチャットを作成・選択・送信したい。Markdown に含まれる危険な内容が実行されてはならない。

**Why this priority**: サイドパネルの制約と既存の安全性・アクセシビリティを満たすための必須品質である。

**Independent Test**: 幅280pxの表示で長文・URL・コード・表を閲覧し、危険な内容を入力・再読込し、主要操作をキーボードのみで完了する。

**Acceptance Scenarios**:

1. **Given** 狭いサイドパネルに長い日本語、長い URL、リスト、コードブロック、表がある、**When** 閲覧・入力する、**Then** 一覧、整形される入力欄、送信ボタンが欠けず、通常の文章は折り返され、幅の広いコードや表はその領域内で横スクロールできる。
2. **Given** スクリプト、イベント属性、危険なリンク、外部画像を含む Markdown がある、**When** 入力欄内の整形表示と保存済みメッセージを表示する、**Then** 任意のプログラム実行、勝手な遷移、外部リソースの自動取得が発生しない。
3. **Given** キーボードのみで操作している、**When** 作成、選択、入力、整形結果の直接編集、送信、エラーからの復旧を行う、**Then** 操作対象と状態を名前で識別でき、フォーカスを失わず、色だけに依存しない。

### Edge Cases

- 連続入力中に以前の描画結果が遅れて届いても、最新の下書きや選択中のチャットを上書きしない。入力を全削除した場合は整形された入力欄も空にする。
- 整形表示の更新待ちにカーソル・選択が移動した場合、古い位置へ戻してはならない。日本語変換中に編集面を置換せず、変換確定後にその場で整形する。
- Backspaceで最後の強調文字を削除しても水平線や古い文字を生成しない。見出しの先頭では段落へ戻し、状態付き項目の先頭では状態を解除し、続けて箇条書きを解除する。段落先頭では前段落と結合し、注意書き本文の先頭では引用から退出する。いずれも周囲の内容を失わない。
- 全選択からのBackspaceは状態表示・注意書きも含めて入力を空にする。連続削除中に遅れた描画で文字や状態を復活させない。
- 同時刻の複数メッセージは別メッセージとして保持し、ファイル内の順序で表示する。日時を識別子として同一視しない。
- 本文内の見出し、引用、箇条書き、コード囲み内の `#`・`##`・`###` をチャット構造と取り違えない。境界が曖昧な既存ファイルは安全に変更を停止する。
- 空ファイル、タイトルなし、重複タイトル、未知のセクション、日時として認識できないメッセージ見出しは、内容を保持して問題の箇所を知らせる。認識できる未知のセクションは名前と順序を保持して閲覧できる。
- 同名タイトルの作成で既存ファイルを上書きしない。LF／CRLF、末尾改行なし、日本語のファイル名でも対象外の内容を変更しない。
- 選択中のファイルの削除・移動、保存先設定の変更、ワークスペース変更でも、対象が不明になった下書きは退避・確認可能にする。
- 送信の連打、保存処理中の追加入力、保存後の一覧更新で重複送信や新しく入力した文字の消失を起こさない。
- 再起動後に復旧する下書きの保存元が変わっている場合は、競合として知らせ、古い内容を自動送信・上書きしない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: サイドパネルは「新しいチャット」、チャット一覧、選択中スレッドを提供しなければならない。旧 TODO/MEMO の分類・カード・作成操作をチャット UI に残してはならない。ユーザー本文内の文字列はこの制約の対象ではない。
- **FR-002**: 1チャットを管理対象ディレクトリ内の1 Markdown ファイルとして扱い、一覧項目とファイルを一対一で対応させなければならない。同名タイトルでも別ファイルを安全に作成できなければならない。
- **FR-003**: チャット構造の `#` はスレッドタイトル、`##` は本文・返信などのセクション、`###` は日時付きメッセージの開始として扱わなければならない。メッセージ本文全体を1メッセージとして扱い、順序と所属セクションを保持しなければならない。
- **FR-004**: タイトル、セクション、日時を本文と区別し、保存済みメッセージの本文を Markdown の整形結果として表示しなければならない。
- **FR-005**: 新規チャットの本文と既存チャットの返信に、Markdown を入力した場所でリアルタイムに整形し、その整形結果を直接編集できる複数行の入力欄を提供しなければならない。入力欄は保存済みメッセージと同じ整形規則を使い、独立したリアルタイムプレビュー領域を設けてはならない。
- **FR-006**: 入力、削除、置換、貼り付け、Undo／Redo に応じて入力欄自体を自動整形しなければならない。送信、保存、改行、フォーカス移動、手動更新、別画面への移動を更新の条件にしてはならない。完成した記法は入力した場所で整形結果を表示し、編集を継続できなければならない。
- **FR-007**: 描画更新は最新の入力と対応するチャットだけに適用し、キャレット、選択範囲、日本語変換、フォーカスを妨げてはならない。変換中の更新を安全のため待つ場合でも、変換確定後に自動更新しなければならない。
- **FR-008**: 見出し、段落、強調、箇条書き、引用、インラインコード、コードブロック、表を入力・表示できなければならない。未完成の Markdown を理由に入力を拒否してはならない。
- **FR-009**: 本文中の通常の `#`・`##`・`###` を利用可能とし、保存・再読込後に同じ見出しの意味とメッセージ境界を保持しなければならない。構造と衝突する本文を黙って分割・変更してはならない。
- **FR-010**: EnterとShift+Enterで送信してはならず、明示的な送信操作でのみメッセージを確定しなければならない。末尾のEnterは見出しから通常段落へ戻し、リストでは次項目を作り、未完了／完了チェック項目では未完了の次項目を作り、注意書きでは内部で改行しなければならない。空項目・空行のEnterはその書式から退出し、Shift+Enterは同じ書式内の改行としなければならない。空白だけのタイトル・メッセージは保存せず、日本語で理由を知らせなければならない。
- **FR-011**: 新規チャットの初回送信時にタイトル、本文セクション、日時付き本文メッセージを保存し、返信送信時には同じファイルの返信セクション末尾へ追加しなければならない。日時はローカル時刻の `YYYY-MM-DD HH:mm` を既定とし、順序は日時ではなくファイル順としなければならない。
- **FR-012**: 未送信入力の描画をチャットファイルの確定保存と結び付けてはならない。下書きはチャット・入力対象ごとに区別し、切替・再表示・再起動時に黙って失われないよう復旧または退避できなければならない。
- **FR-013**: 保存成功後に送信済みメッセージと一覧を更新し、送信した下書きだけを消去しなければならない。処理中の二重送信を防ぎ、その間に追加された入力を消してはならない。
- **FR-014**: 対象以外のファイル、既存メッセージ、未知の内容、改行形式を保持しなければならない。送信のために既存ファイル全体を無断変換してはならない。
- **FR-015**: 管理対象 Markdown の直接編集、作成、削除、移動を既存の変更検知に合わせて一覧・選択中スレッドに反映しなければならない。VS Code の原文エディタの未保存変更も一覧タイトル・スレッドに反映し、「原文に未保存の変更あり」と明示しなければならない。保存または破棄後は最新内容と状態表示に更新しなければならない。下書きは表示更新で上書きしてはならない。
- **FR-016**: 競合、他の未保存編集、読み取り専用、保存失敗、対象消失では安全な更新を停止し、失敗理由、入力のコピー・退避、原文を開く、最新状態の再読込、再試行の手段を提供しなければならない。他の編集を勝手に保存・破棄してはならない。対象チャットの原文に未保存変更がある間は送信と送信済みチェック項目の切替保存を停止し、原文の保存または破棄後に下書きの保存元と最新内容を照合し、差異がある場合は競合として確認を求めなければならない。競合時も下書きを保持し、自動送信・自動上書きしてはならない。ユーザーが明示的に再試行を選んだ場合に限り、最新文書・対象 section または task を再解析し、対象が一意に存在し、安全な追記または対象 marker のみの更新ができることを確認してから操作する。確認後の送信は既存内容を置換せず、新規 message の追記に限る。
- **FR-017**: チャット形式ではない既存ファイルや曖昧・不正な構造は、一覧で識別可能にして理由と元の Markdown を開く手段を提供しなければならない。黙って除外・移行・上書きしてはならない。既存の原文編集・閲覧手段を維持しなければならない。
- **FR-018**: 未知のセクションも安全に識別できる場合は名前・本文・順序を保持して表示しなければならない。識別できない場合は読み取り専用として問題を知らせなければならない。
- **FR-019**: 入力欄内の整形表示と保存済みメッセージの双方で、Markdown 由来のスクリプト、イベント属性、危険なリンクによる任意実行や勝手な遷移を許可してはならない。外部画像等を無条件に取得してはならず、既存の表示領域のセキュリティ制限を弱めてはならない。
- **FR-020**: 幅280px以上で通常の文章・日本語・長い URL を折り返し、コード・表の横スクロールをその領域内に限定しなければならない。パネル全体の横スクロール、隠れる入力欄・送信操作を生じさせてはならない。
- **FR-021**: 作成、選択、入力、整形結果の直接編集、送信、原文表示、復旧をキーボードだけで行えなければならない。ラベル・状態・エラーは日本語で示し、色やアイコンだけに依存してはならない。
- **FR-022**: 既存の Markdown 描画・編集・下書き・変更検知・保存の仕組みを調査し、再利用可能な機能を優先しなければならない。新しい描画基盤や依存関係を無条件に追加してはならず、必要な変更と理由は計画に記録しなければならない。
- **FR-023**: Markdown ファイルは拡張機能なしでも内容を読み、編集できなければならない。本文内の見出しとチャット境界を区別する保存規則は、通常の Markdown としての可読性を保ち、計画時に根拠・代替案・復旧方法を明記しなければならない。
- **FR-024**: 保存先設定と管理対象範囲の制約、Windows・macOS・Linux 対応を維持しなければならない。ワークスペースや保存先が利用できない場合は、空状態と必要な操作を明示しなければならない。
- **FR-025**: メッセージ本文内の `- [ ]`／`- [x]` を未完了／完了のチェック表示として区別し、入力欄・送信済みメッセージの双方でクリックとキーボードによる切替を提供しなければならない。入力欄では下書きだけを変更し、送信済み側では対象項目の状態だけを安全に保存しなければならない。未保存の原文変更・競合・読み取り専用・保存失敗では切替保存を停止し、理由と未確定状態を示し、既存本文・下書きを保持しなければならない。`- [i]`／`- [!]`／`- [n]`／`- [-]` は既存のIMP／WARN／Note／Skipの名前付き表示として扱い、チェック切替で勝手に別状態へ変えてはならない。これは旧Todo一覧の復活ではなく本文内の操作である。装飾をMarkdown本文として誤保存してはならない。
- **FR-026**: `> [!INFO]`／`> [!WARN]` を名前付きの注意書きブロックとして入力欄と送信済みメッセージに表示し、本文・種類を編集と送信で保持しなければならない。見出しのレベルは字体の大きさと強調で区別し、状態付き項目の本文は通常の本文サイズで表示しなければならない。
- **FR-027**: Backspaceは通常文字の削除、選択範囲の削除、書式の先頭での解除、段落の結合、全削除を内容損失なしに行えなければならない。最後の文字の削除で不要な記法・水平線を生成せず、連続削除やUndo／Redoで古い描画を復活させてはならない。

### Key Entities

- **チャット／スレッド**: 1 Markdown ファイルに対応する会話。保存先、タイトル、順序付きセクションを持つ。一覧と表示の選択対象となる。
- **セクション**: 本文、返信などの名前付きメッセージ群。スレッドに所属し、ファイル内の順序を持つ。
- **メッセージ**: セクションに属する日時付きの Markdown 本文全体。同時刻でも別メッセージとして扱う。
- **下書き**: 本文または返信の未送信入力。対象チャット、元の保存状態、入力内容、復旧・競合状態を持ち、送信済みメッセージとは区別する。
- **描画結果**: 保存済みメッセージまたは最新の下書きの安全な整形表示。元の Markdown の代わりに保存するデータではない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 1,000行かつ32,000文字以内の下書きに100回の入力・削除・貼り付け・Undo／Redo を行った場合、95回以上で操作後500ミリ秒以内に入力欄そのものが最新の整形結果を表示する。日本語変換は確定後から測定する。送信・保存・手動更新操作と別枠プレビューの利用は0回である。
- **SC-002**: 見出し、強調、リスト、引用、コード、表、日本語を含む受入例のすべてで、入力中と送信後・再読込後の整形結果、メッセージ数・所属・順序が一致する。本文の見出しによる誤分割は0件である。
- **SC-003**: 新規チャット1件と返信2件の作成を、別エディタや別プレビューへ移動せず完了でき、追加されるチャットファイルは正確に1つである。保存成功後2秒以内に一覧とスレッドへ反映される。
- **SC-004**: 外部編集・作成・削除・移動、原文の未保存変更・保存・破棄の確認ケースすべてで、変更後2秒以内に対象の一覧・スレッドを更新するか、変更を安全に反映できない理由を表示する。未保存の原文変更がある全ケースで未保存状態を明示して送信を停止する。下書きの無警告消失、古い内容による上書き、重複送信、無関係なファイル変更は各0件である。
- **SC-005**: スクリプト、イベント属性、危険なリンク、外部画像の受入例について、入力中と保存後の双方で任意実行、勝手な遷移、外部リソース自動取得が各0件である。
- **SC-006**: 幅280px・400px・800pxで長い日本語、200文字の連続 URL、幅の広いコード、表を含むスレッドを表示しても、パネル全体の横方向のはみ出しと主要操作の欠落は0件である。
- **SC-007**: キーボードだけで新規作成、チャット選択、本文・返信の入力、整形結果の直接編集、送信、原文表示、失敗時の退避を完了できる。日本語変換を含む10段落の入力で文字の欠落・重複、意図しないキャレット・選択位置の移動は各0件であり、保存済み・未送信・保存失敗を色なしで識別できる。
- **SC-008**: 提供するチャット UI に旧 TODO/MEMO の分類・操作 UI が0件である。互換性確認の全ケースで、既存ファイルを無変更のまま原文で閲覧・編集でき、対応できない形式を識別できる。
- **SC-009**: 入力欄と送信済みメッセージのチェック切替をクリック・キーボードでそれぞれ行い、対象項目だけが変わる。送信済み側は保存・再読込後も状態が100%一致する。競合・未保存原文・読み取り専用・保存失敗の各ケースで、他項目・本文・下書きの消失や成功の誤表示は各0件である。

## Assumptions

- 対象は個人がワークスペース内のファイルで管理するローカルなチャット形式のノートである。Teams は入力・閲覧体験の参考であり、共同編集、参加者、認証、オンライン送信、AI 応答、外部サービス連携は対象外とする。
- 2026-10-04の確認で、本文内の `#`・`##`・`###` は通常の見出しとして利用でき、送信・再読込後も同じ表示とメッセージ境界を保持することが選択された。保存時の区別方法は計画で決める。本文の見出しを `####` 以下に限定しない。
- 新規チャットはタイトルと最初の本文を入力して初回送信時にファイルを作成する。本文セクションの初回メッセージは1件とし、以後は返信を追加する。既存ファイル内に複数の本文メッセージがある場合はすべて閲覧する。
- 一覧は既存の更新日時の降順を基本とし、同時刻のファイルは保存先による安定順序とする。タイトルは構造用の見出しを用い、ファイル名と表示タイトルを同一とする必要はない。
- 本機能はチャット UI を既定のサイドパネル体験にする意図的な変更であり、従来の Todo 専用の管理画面・ラベル・属性操作をチャットへ追加しない。本文内の未完了／完了チェック切替は入力欄・送信済み側とも対象に含める。既存データを自動移行せず、非対応ファイルは識別と原文への導線で保護する。既存ファイルの一括移行、送信済みメッセージの本文編集・削除（チェック切替を除く）、スレッド削除は対象外とする。
- 既存の管理対象ディレクトリ設定、最初のワークスペースフォルダーを使用する規則、安全な命名、変更検知、競合検出、下書き復旧、原文編集を前提とする。既存の仕組みが対応しないチャット特有の挙動は計画で補う。
- 500ミリ秒の描画目標と2秒の表示更新目標は検証可能な初期基準であり、受入確認では対象 OS、文書サイズ、表示幅を記録する。性能測定の文書サイズは入力の上限を意味しない。
- 既存の安全な Markdown 表示に合わせ、リンクは読める表示を優先し、外部画像を自動取得しない。任意 HTML の実行・装飾は提供範囲に含めない。
- 専用のチャット表示は、会話の文脈と送信前の整形結果を入力した場所で確認・直接編集できる価値のために必要である。2026-10-04の追加フィードバックにより、入力欄と別のプレビューを並べる初期案は取り下げた。Markdown 由来の整形表示の直接編集は対象に含め、任意の書式ツールバーや独立した汎用エディタの新設は求めない。
