## User Scenarios & Testing *(mandatory)*

### User Story 1 - Todo に課題と対応方針を残す（要望003） (Priority: 未決定)

ユーザーは、Todo の短いタイトルとは別に、課題の背景、調査内容、対応方針や進捗を複数行で記録し、後から読み返して追記・修正したい。

**Why this priority**: 作業の文脈を残す価値を、他の機能のユーザーストーリーと比較して優先順位と実際の提供範囲を決めるため、未決定とする。

**Independent Test**: タイトルのみの既存 Todo を開き、課題と対応方針を複数段落で追記して保存し、再度開いて確認する。優先度、サイドパネル編集、ライブ編集が未提供でも検証できる。

**Acceptance Scenarios**:

1. **Given** タイトルのみの Todo がある、**When** その項目の詳細メモを開く、**Then** タイトルと空の詳細メモが区別され、既存内容は変更されない。
2. **Given** Todo の詳細を編集している、**When** 課題と対応方針を見出し・段落・箇条書きで入力して保存する、**Then** 再表示・再起動後も同じ Todo に結び付いた内容として読める。
3. **Given** 詳細メモ付き Todo がある、**When** タイトルまたは状態を変更する、**Then** 詳細メモは保持される。詳細メモのみの修正・消去ではタイトル、状態、他の Todo は変わらない。
4. **Given** 同名の Todo が同一ファイルと別ファイルに存在する、**When** 1件の詳細メモを変更する、**Then** 選択した1件だけが変更される。
5. **Given** 詳細メモ付き Todo がある、**When** 削除を要求する、**Then** 詳細メモも削除対象であると明示され、キャンセルすれば両方が残り、承認すれば対象 Todo とその詳細だけが削除される。

### Edge Cases

- 詳細メモ中の空行、見出し、箇条書き、チェックボックス風の文章と隣接 Todo の境界を取り違えない。詳細内のチェックボックスは本機能では独立した Todo として一覧・件数に含めない。
- タイトルだけの旧形式、LF／CRLF、日本語、同名 Todo、末尾改行がない文書を扱っても、対象外の本文や改行形式を変更しない。
- 未知の記法や曖昧な詳細の所属がある場合は、内容を破棄せず「認識できない Todo」として読み取り専用で示し、生 Markdown での修正へ案内する。004が提供されている場合、不明な優先度も同様に扱う。
- 外部変更、削除・移動、読み取り専用、保存失敗が起きても、古い内容による上書きや成功表示をせず、入力を退避できる。再起動を伴う場合は終了前に標準の未保存確認または退避手段を提供する。
- 詳細メモの表示中に未完成の Markdown や外部コンテンツを含んでも、入力を拒否したり外部スクリプトを実行したりせず、安全な表示を継続する。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-301**: 各 Todo は必須のタイトルと任意の複数行詳細メモを持ち、ユーザーは両者を区別して閲覧・編集できなければならない。タイトルのみでの作成も継続して利用できる。
- **FR-302**: 詳細メモは段落、見出し、箇条書き、リンクを含む Markdown として記録でき、保存・再表示・再起動後も対象 Todo との対応を保持しなければならない。
- **FR-303**: 詳細の変更は当該 Todo の詳細だけに適用し、タイトル・状態や隣接項目を変更してはならない。他の属性の変更も詳細を失わせてはならない。004が提供されている場合は優先度・ラベルについても相互に保持するが、その提供は本機能の受入条件ではない。
- **FR-304**: Todo の削除時は詳細も削除することを確認し、キャンセル時は何も変更してはならない。詳細の所属が曖昧な場合は削除せず警告する。
- **FR-305**: 詳細メモも通常の Markdown ファイルに保存し、拡張機能なしでも項目との対応と内容を読んで編集できなければならない。生 Markdown 表示への切替を常に残す。具体的な表記は計画段階で決めるが、既存内容の一括変換を導入条件にしてはならない。
- **FR-306**: 競合時は古い内容を黙って上書きせず、失敗理由と再読込・再試行の案内を示し、未反映の入力をコピーして退避できなければならない。既に未保存の他の編集を意図せず保存・破棄してはならない。
- **FR-307**: 未知の記法や曖昧な Todo は読み取り専用として知らせ、対象外の内容、改行形式、同名の別項目を保持しなければならない。詳細メモ内のチェックボックスを独立 Todo として二重計上してはならない。
- **FR-308**: 新しい操作はキーボードだけで利用でき、状態・保存結果を色だけに依存せず名前で識別できなければならない。004が提供されている場合、その優先度・ラベルも同様とする。日本語 UI と既存の Windows・macOS・Linux 対応を維持する。
- **FR-309**: Markdown 内の外部スクリプトを実行せず、リモート画像を自動取得してはならない。編集・保存は既存の管理対象だけで行い、表示内容により無関係なファイルを変更してはならない。
- **FR-310**: 001／002の既存 Todo は明示的な変換なしで読み取れ、6状態の選択・変更と未解決件数（未完了・Warn・IMP の合計）を維持しなければならない。本機能単独では既存の並び順を変更しない。
- **FR-311**: 003〜006で扱う Todo／タスクカードは担当者属性を持たない個人用項目とし、担当者の割り当て・表示・保存・権限制御を本機能で追加してはならない。

### Key Entities

- **Todo**: 所属するメモ、必須のタイトル、既存の状態、任意の詳細メモを持つ個人用の作業項目。同名でも別項目として扱い、担当者属性は持たない。004が提供される場合の優先度・ラベルは本仕様では追加しない。
- **詳細メモ**: 1件の Todo に属する任意の複数行 Markdown。課題、対応方針、進捗を自由に記録する。
- **編集中の入力**: 文書への反映・保存が終わっていない変更。保存状態、競合、退避可能性をユーザーに示す対象。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-301**: タイトルのみ、複数段落、同名項目、異なる状態を含む10件の Todo で、詳細を保存して再起動しても、タイトル・状態・詳細と所属が全件一致し、対象外の変更が0件である。優先度・ラベルは検証の前提にしない。
- **SC-302**: 競合・保存失敗・外部での削除や移動・曖昧な詳細の所属・詳細内のチェックボックスを含む境界ケースで、未保存入力の無警告消失、対象外内容の意図しない変更、Todo の二重計上が各0件である。外部スクリプト実行・リモート画像自動取得も各0件である。
- **SC-303**: 既存の6状態、タイトルのみの Todo、通常メモについて、閲覧・変更・保存・生 Markdown 切替の回帰確認がすべて成功し、本機能による既存の並び順と未解決件数の変更が0件である。
- **SC-304**: 本 User Story の閲覧・追記・修正・消去・削除確認の主要操作をキーボードのみで完了でき、状態・保存結果を色を使わず識別できる。利用確認で各操作後に「何を記録したか」「保存できたか」を確認できることを合格条件とする。

## Assumptions

- 本文の具体的な挙動・既定値は、既存仕様から引き継いだ検証可能な初期案であり、ユーザーによる承認済みの決定ではない。優先順位と実際の提供範囲は003〜006の全ストーリーを比較して決める。
- 詳細は任意の Markdown とし、その中のチェックボックスは独立 Todo にしない案とする。詳細の消去と Todo 自体の削除は区別する。
- 既存の管理対象ディレクトリ、最初のワークスペースフォルダーを使用する規則、メモの命名、保存・復旧の仕組みを前提とする。共同編集や外部プロセスとの排他制御は追加しない。
- データの具体的な Markdown 表記と表示方式は計画段階で決定する。その際、詳細の境界、既存 Todo との識別、外部編集後の再読込、破損時の復旧を検証する。拡張機能だけで読めるデータ形式を前提にしない。
- 対象外の従来機能は維持する。既存仕様との差分は Todo 詳細の追加であり、優先度・ラベル、サイドパネルでの入力、連続ライブ編集、別の保存領域やチャット機能は本仕様の対象外とする。
- 003〜006で扱う Todo／タスクカードは個人用項目とし、担当者の割り当てや共有ワークフローは導入しない。
