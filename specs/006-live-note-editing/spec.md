## User Scenarios & Testing *(mandatory)*

### User Story 1 - 改行で編集を中断しないライブ編集（要望006） (Priority: 未決定)

ユーザーは、メモのレンダリング画面で、行ごとに編集箇所を開いたり確定したりせず、文章を連続して入力したい。入力した見出しや強調などの結果を、別画面に移らずその場で確認したい。

**Why this priority**: 長い文章を分断せずに入力する価値を、他の機能のユーザーストーリーと比較して優先順位と実際の提供範囲を決めるため、未決定とする。

**Independent Test**: 通常メモのレンダリング画面で複数段落を連続入力し、改行、段落をまたぐ選択・置換、貼り付け、Undo／Redo を実行する。Todo 拡張やサイドパネル入力に依存しない。

**Acceptance Scenarios**:

1. **Given** 空のメモまたは既存の段落を編集している、**When** Enter を含めて複数段落を連続入力する、**Then** Enter は改行または段落の作成として働き、編集終了・送信・次の行の編集開始操作を要求しない。
2. **Given** 複数段落を編集している、**When** 段落境界をまたいで選択・置換・削除し、複数行を貼り付ける、**Then** 一続きの編集として操作でき、選択範囲外の内容は変わらない。
3. **Given** 見出し・強調・通常の箇条書きを入力している、**When** 表示可能な記法まで入力する、**Then** 保存・改行・フォーカス移動を待たずに同じ編集面で整形結果を確認でき、入力位置や選択が別の場所に飛ばない。
4. **Given** 日本語を変換入力している、**When** 変換候補の選択と確定を行う、**Then** 自動表示更新が変換を中断せず、文字の欠落・重複や意図しない改行が生じない。
5. **Given** 複数段落の変更を行った、**When** Undo／Redo、保存、生 Markdown 表示への切替、再表示を行う、**Then** 変更を取り消し・再適用でき、最終的な本文と Markdown の意味が一致する。
6. **Given** テーブルやコードブロックなど直接編集の対象外の構造を含む、**When** 周辺の文章を編集する、**Then** 対象外の内容は保持される。その構造自体またはそれをまたぐ範囲を編集しようとした場合は、生 Markdown での編集へ案内され、変更は黙って適用されない。

### Edge Cases

- タイトルだけの旧形式の Todo を含むメモ、LF／CRLF、日本語、同名 Todo、末尾改行がない文書を扱っても、意図した編集範囲外の本文や改行形式を変更しない。
- 外部変更、削除・移動、読み取り専用、保存失敗が起きても、古い内容による上書きや成功表示をせず、入力を退避できる。再起動を伴う場合は終了前に標準の未保存確認または退避手段を提供する。
- レンダリング中に未完成の Markdown や外部コンテンツを含んでも、入力を拒否したり外部スクリプトを実行したりせず、安全な表示を継続する。
- 日本語の変換中入力や長文貼り付けでキャレット・選択範囲を失わない。空のメモからも連続入力でき、通常の改行や対応する段落間の編集を対象外として扱わない。
- 未知の Todo 記法は自動処理で変更しない。003・004が提供されている場合は詳細の境界や不明な優先度にも同じ保護を適用するが、それらの提供は受入条件ではない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-601**: メモのレンダリング画面は、段落・見出し・通常の箇条書きを一続きに編集でき、Enter、複数行の貼り付け、段落をまたぐ選択・削除・置換を提供しなければならない。行または段落ごとの編集開始・確定操作を要求してはならない。
- **FR-602**: 入力に応じた整形結果を同じ編集面に自動反映しなければならない。保存・改行・フォーカス移動や別プレビューの再読込を反映条件にしてはならない。未完成の記法は入力を保持してテキストとして扱ってよい。
- **FR-603**: 自動反映は、キャレット、選択範囲、日本語の変換中入力を妨げてはならない。通常の保存と Undo／Redo を利用でき、表示切替によって未保存の編集履歴を失ってはならない。
- **FR-604**: 直接編集の対象外の構造は保護し、その構造を含む編集には生 Markdown への切替手段と理由を示さなければならない。周辺の対応済み文章の連続編集は妨げず、対象外の記法を黙って書き換えてはならない。
- **FR-605**: 通常メモは通常の Markdown ファイルに保存し、拡張機能なしでも内容を読んで編集できなければならない。生 Markdown 表示への切替を常に残し、既存内容の一括変換を導入条件にしてはならない。
- **FR-606**: 競合時は古い内容を黙って上書きせず、失敗理由と再読込・再試行の案内を示し、未反映の入力をコピーして退避できなければならない。既に未保存の他の編集を意図せず保存・破棄してはならない。保存済み・未保存・保存失敗を区別し、メモや表示モードの切替でも未保存入力を黙って破棄してはならない。
- **FR-607**: 意図した編集範囲外の内容、改行形式、同名の別項目を保持しなければならない。未知の記法や曖昧な Todo を Todo 操作では読み取り専用として知らせ、生 Markdown での修正へ案内する。003が提供されている場合、詳細内のチェックボックスを独立 Todo として二重計上してはならない。
- **FR-608**: 新しい操作はキーボードだけで利用でき、状態・保存結果を色だけに依存せず名前で識別できなければならない。004が提供され表示する場合は優先度・ラベルも同様とする。日本語 UI と既存の Windows・macOS・Linux 対応を維持する。
- **FR-609**: Markdown 内の外部スクリプトを実行せず、リモート画像を自動取得してはならない。編集・保存は既存の管理対象だけで行い、表示内容により無関係なファイルを変更してはならない。
- **FR-610**: 003〜006で扱う Todo／タスクカードは担当者属性を持たない個人用項目とし、連続編集画面から担当者の割り当て・表示・保存・権限制御を追加してはならない。

### Key Entities

- **通常メモ**: 連続編集する Markdown 文書。生 Markdown 表示とレンダリング画面は同じ文書を扱い、サイドパネル入力は前提にしない。
- **編集中の入力**: 文書への反映・保存が終わっていない変更。キャレット・選択範囲・変換中入力・編集履歴を保持し、保存状態、競合、退避可能性をユーザーに示す対象。
- **直接編集の対象外の構造**: テーブル、コードブロック、画像、複雑なネストなど、生 Markdown で編集する保護対象。周辺の対応済み文章とは区別する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-601**: 10段落の連続入力・段落をまたぐ置換・複数行貼り付けを、行ごとの編集開始／確定操作0回で完了でき、日本語変換を含め入力の欠落・重複が0件である。
- **SC-602**: 1,000行以内のメモにおける100回の表示可能な記法の入力で、95回以上は入力後500ミリ秒以内に同じ編集面で整形結果を確認できる。変換中の日本語は変換確定後から測定する。
- **SC-603**: 競合・保存失敗・表示切替・対象外構造・外部での削除や移動を含む境界ケースで、未保存入力の無警告消失と対象外内容の意図しない変更が各0件である。外部スクリプト実行・リモート画像自動取得も各0件である。
- **SC-604**: 既存の6状態、タイトルのみの Todo、通常メモについて、閲覧・変更・保存・生 Markdown 切替の回帰確認がすべて成功する。002の行・ブロック単位の限定編集は連続編集への意図した変更として評価し、Undo／Redoと再表示後の最終的な本文・Markdown の意味が100%一致する。
- **SC-605**: 本 User Story の連続入力・選択・置換・削除・貼り付け・Undo／Redo・保存・表示切替をキーボードのみで完了でき、状態・保存結果を色を使わず識別できる。利用確認で各操作後に「何を記録したか」「保存できたか」を確認できることを合格条件とする。

## Assumptions

- 本文の具体的な挙動・既定値は、既存仕様から引き継いだ検証可能な初期案であり、ユーザーによる承認済みの決定ではない。優先順位と実際の提供範囲は003〜006の全ストーリーを比較して決める。
- Teams／GPT は途切れない入力体験の参考であり、チャット、送信、AI 生成、外部サービス連携を求めるものではない。
- 要望006は002の行・ブロック単位の限定編集を置き換える。本仕様の連続直接編集は段落・見出し・通常の箇条書きを対象とする初期案で、テーブル、コードブロック、画像、複雑なネストの直接編集や任意のリッチテキスト機能は対象外とする。通常の改行や対応する段落間の編集を対象外として扱ってはならない。
- 未完成の記法は入力を保持してテキストとして扱える案とする。表示方式は計画段階で決定し、外部編集後の再読込、対象外構造の保護、破損時の復旧を検証する。1,000行・500ミリ秒の性能基準も引き継いだ初期案とする。
- 既存の管理対象ディレクトリ、最初のワークスペースフォルダーを使用する規則、メモの命名、保存・復旧の仕組みを前提とする。共同編集や外部プロセスとの排他制御は追加しない。拡張機能だけで読めるデータ形式を前提にしない。
- 対象外の従来機能は維持する。既存仕様との差分は002の限定編集から連続編集への拡張であり、Todo 属性・並び順、サイドパネル入力、別の保存領域は追加しない。
- 003〜006で扱う Todo／タスクカードは個人用項目とし、担当者の割り当てや共有ワークフローは導入しない。
