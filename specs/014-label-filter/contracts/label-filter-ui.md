# Contract: Issue 一覧のラベル絞り込み

## Scope and behavior

- Issue一覧に検索語・状態と併用できる単一ラベル選択を表示する。
- 候補は検索語・状態・選択中ラベルで絞る前の有効なIssue全体から取得する。重複ラベルは候補上で一つにまとめ、安定した順序で表示する。
- ラベル条件が未選択なら既存の検索語・状態だけを適用する。選択時は全条件に一致するIssueだけを表示する。
- 「ラベルなし」または「条件を解除」の選択で、検索語・状態を保ったままラベル条件だけを解除できる。
- 候補を選択するだけではIssueを編集しない。絞り込み、解除ともにIssue Markdown、コメント、更新日時に変更を加えない。
- 詳細から一覧に戻ると条件と選択状態を復元する。アプリ再起動後の永続化はしない。
- 検索結果なしは、Issue未作成の状態と区別して表示する。Issueが一件もない状態、検索・フィルターに一致しない状態、一覧読み込みエラーを混同しない。

## Selection and accessibility

- 選択条件と解除手段を文字で示し、色だけに依存しない。
- キーボードのみで候補を選択・解除できる。
- 操作には日本語のアクセシブルな名前を付け、選択中のラベルが支援技術で識別できる。
- 候補の読み込みに失敗した場合、空の候補一覧として黙って扱わず、既存の一覧読み込み失敗経路に従って理由を示す。

## State and message contract

- 一覧条件の更新は、既存の検索語と状態条件を維持したままラベル条件を渡せる。
- ラベル値は文字列または未選択を表す値とし、型・長さをホスト側で検証する。不正なメッセージや未知フィールドは無視し、Issue保存処理へ渡さない。
- 一覧snapshotは候補ラベルと選択中ラベルを区別して伝える。選択中ラベルが結果0件でも条件を保持する。
- snapshotに含む候補は有効Issueに実在するラベルのみ。Issue本文・ファイルURIなどを候補データに含めない。

## Verification invariants

- 絞り込み後のIssueは検索語・状態・選択ラベルの全条件を満たす。
- 大文字小文字の違うラベルは異なる条件として扱う。既存値の前後空白は保存時のルールに従って扱う。
- ラベル条件解除後、検索語と状態条件は変化しない。
- 条件の適用・解除前後でIssueファイルの内容と更新日時が変化しない。
