# Feature Specification: Issue 一覧のラベル絞り込み

**Feature Branch**: `014-label-filter`

**Created**: 2026-10-24

**Status**: Draft

**Input**: User description: "ラベルの絞り込みを対応しようか"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ラベルで Issue を絞り込む (Priority: P1)

利用者は Issue 一覧でラベルを選び、そのラベルが付いた Issue だけを確認できる。

**Why this priority**: ラベルを使って Issue を分類する価値を、一覧から関連する Issue を探す操作に結び付けるため。

**Independent Test**: 異なるラベルを付けた Issue がある状態でラベルを選び、選択したラベルを持つ Issue だけが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 異なるラベルを持つ Issue が一覧にある、**When** 利用者がラベルを選ぶ、**Then** そのラベルが付いた Issue だけが表示される。
2. **Given** ラベルで絞り込まれている、**When** 利用者がラベル条件を解除する、**Then** ラベル条件を除いた一覧に戻る。
3. **Given** 選んだラベルを持つ Issue がない、**When** そのラベルで絞り込む、**Then** Issue がまだない状態とは区別して検索結果がないことを確認できる。

---

### User Story 2 - 他の一覧条件と組み合わせる (Priority: P2)

利用者は検索語、Open／Closed の状態、ラベルを組み合わせて、目的の Issue を絞り込める。

**Why this priority**: 条件を組み合わせることで、Issue が増えても目的の項目を見つけやすくするため。

**Independent Test**: 検索語・状態・ラベルがそれぞれ異なる複数の Issue を用意し、条件を組み合わせて一致するものだけが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 検索語・状態・ラベルに一致する Issue がある、**When** 利用者がそれらの条件を組み合わせる、**Then** すべての指定条件に一致する Issue だけが表示される。
2. **Given** 複数の一覧条件が有効である、**When** 利用者がラベル条件だけを解除する、**Then** 検索語と状態条件を維持した一覧が表示される。

---

### User Story 3 - 詳細を確認して一覧に戻る (Priority: P3)

利用者は絞り込み結果から Issue の詳細を確認し、一覧に戻った後も絞り込み条件を保てる。

**Why this priority**: Issue を順に確認する際に、検索条件を何度も設定し直す手間をなくすため。

**Independent Test**: 条件を設定して Issue の詳細を開き、一覧へ戻ったときに条件と結果が維持されることを確認する。

**Acceptance Scenarios**:

1. **Given** ラベルを含む条件で絞り込んだ一覧がある、**When** 利用者が詳細を開いて一覧へ戻る、**Then** 選択条件と絞り込み結果が維持される。

---

### Edge Cases

- 選択したラベルに一致する Issue がない場合も、空の Issue 一覧とは異なる検索結果なしの表示にする。
- Issue にラベルがない場合、ラベルによる絞り込みでは表示しない。
- ラベルの比較では大文字・小文字を区別し、保存済みラベルの前後空白を除去した表記を用いる。
- 絞り込みの解除では、他の有効な検索条件を解除しない。
- 絞り込み条件の変更だけでは Issue の内容や更新日時を変更しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Issue 一覧で、ワークスペース内の有効な Issue に付いているラベルを選択して絞り込めること。ラベル候補は現在の検索結果だけに限定しないこと。
- **FR-002**: 初期対応では一度に選択できるラベルを1つとし、条件を解除する操作を提供すること。
- **FR-003**: 検索語、Open／Closed の状態、選択したラベルを同時に適用し、指定されたすべての条件に一致する Issue だけを表示すること。
- **FR-004**: 選択中のラベル条件を画面上で識別でき、解除後も検索語と状態条件を維持すること。
- **FR-005**: 絞り込み結果がない場合に、Issue が未作成の状態と区別できる案内を表示すること。
- **FR-006**: 詳細を開いて一覧へ戻った場合、検索語・状態・ラベルの条件を維持すること。アプリ再起動後の条件保持は対象外とする。
- **FR-007**: ラベルの照合で前後の空白を除いた既存の表記ルールを用い、大文字・小文字を区別すること。
- **FR-008**: 閲覧条件の変更だけでは Issue の内容、保存ファイル、更新日時を変更しないこと。

### Key Entities *(include if feature involves data)*

- **Issue**: タイトル、本文、Open／Closed の状態、および0個以上のラベルを持つ項目。
- **一覧条件**: Issue の一覧を絞り込む検索語、状態、および選択中のラベル。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ラベルを1つ選ぶと、そのラベルを持つ Issue だけが表示され、選択した条件と表示結果が一致する。
- **SC-002**: 検索語・状態・ラベルを組み合わせた確認で、表示される Issue がすべての指定条件を満たす。
- **SC-003**: 詳細から一覧へ戻った後も、設定済みのすべての一覧条件が維持される。
- **SC-004**: 絞り込み条件の変更前後で Issue の内容と更新日時に差が生じない。

## Assumptions

- ラベルは既存の Issue に保存されている値を使用し、ラベルを作成・編集する機能は追加しない。
- 初期版は単一ラベル選択とし、複数ラベル選択は対象外とする。
- ラベル候補は、現在の検索条件に関係なく、ワークスペース内の有効な Issue から得る。
- 選択条件の保持は現在の画面操作中に限り、アプリ再起動をまたぐ永続化は行わない。
